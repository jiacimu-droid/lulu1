# 露露机：3D 角色 / 数字世界 / 虚拟视频通话实施方案

> 2026-10-09 产品方向：**风格化二次元 3D 是主形态**；Live2D 仅作兼容或轻量模式，不以真人超写实为目标。
> 本文件是工程实施约定，并不表示仓库目前已有能运行的 3D 引擎、角色模型或虚拟视频通话。

## 1. 不变的权威来源

- 角色定义：`CharacterRuntime`、`CharacterInnerLifeStore`、`CharacterDevelopmentStore`。
- 地点、房屋、摆设、家具、人物位置：`DigitalWorldStore`。
- 持续事件和现场事实：`DigitalWorldLifeEventStore`、现有世界事件执行器。
- 见面场景角色状态与交互：`DigitalWorldMeetingGenerationV2`、`MeetingExperienceStore`、`MeetingSession`。
- 实际发声与音频播放回执：现有电话/TTS 系统。
- 共同时间线和证据：`SharedExperienceTimeline`。
- **Godot 负责画面渲染、物理和动作执行；不得自立另一套角色记忆、家具数据或事件事实。** 模型提出意图不等于视觉事件发生。

## 2. 技术选型及边界

1. 优先做 Godot 4 的 Android AAR/独立 Activity 试验，复用已有 Android/Kotlin 项目；Godot 官方文档支持作为 Android 库被嵌入，但 Android 方向旋转处理与单进程单引擎存在限制。第一期不要强行在全部 Compose 页面直接嵌入 Fragment。
2. 角色优先用 VRM 1.0 / MToon 风格化材质；Godot 引入兼容的 VRM 导入插件（例如 V-Sekai/godot-vrm），锁定并验证引擎与插件版本，特别实测 VRM 1.0 表情、视线和头发骨骼。模型来源可用 VRoid Studio 先建立原创原型；模型、服装与第三方资源逐个核实再分发许可。
3. 家具/房间使用 glTF/GLB；Kotlin 保存稳定对象 ID，Godot 使用资源标识加载几何，不让生成文本直接充当 Mesh 或碰撞体。
4. 初版只在一个已确认真实存在的房间加载一名角色、一台手机摄像机和少量有碰撞/声音的物品；性能稳定以后再扩展公共场所与多角色。
5. **APK 文件可以大，但每帧 GPU、内存、发热与耗电仍是实际限制。** 使用 LOD、按场景加载、压缩材质、对象复用和帧率自适应。20MB 不是上限，10GB 也不是交互质量的保证。

## 3. 角色视觉状态机（不靠随机动作凑活人感）

基础层（可以叠加，且均保留一个人的身份）：

- `idle` 呼吸/重心/眨眼；`gaze` 看向当前兴趣点/用户镜头/真正掉落的物件。
- `face` 面部 blendshape：眉、眼、嘴、脸红与情绪强弱；短时间内保留情绪惯性，不按每个标点切表情。
- `speech` 从已播放音频的能量/可用音素或口型时间戳驱动嘴型，严禁单靠模型说“我在讲话”冒充口型同步。
- `gesture` 根据事件、人格、双方距离、可达性、角色当前姿态执行已存在动作：低头、扭头、抬下巴、抱臂、后退、耸肩、指向物品、拿起手机。
- `locomotion` 真正在导航网格里移动，有转向、碰撞、手持状态和失败回执。
- `interaction` 看/拿/放/使用家具或事件对象，必须通过执行器验证权限、碰撞、距离和姿态。

高频微动作可以由动画层插值，而不需要每秒发一次大模型请求；**只有影响世界的动作走真实执行事件链**。例如尴尬可以先看开用户→短暂停顿→转回；角色也可能继续直视，取决于个性。

## 4. 持久三维场景的统一契约（拟新增，不要现在伪装已有）

现有家具 `DigitalWorldItem.position` 是中文位置描述，尚不是可碰撞的三维坐标。新增版本化 `WorldSpatialSnapshot` 与 `WorldVisualEvent`，不要覆盖原存档：

```json
{
  "version": 1,
  "sceneId": "home:character-id",
  "revision": 45,
  "entities": [
    {
      "entityId": "existing-persistent-furniture-id",
      "assetId": "chair_wood_01",
      "transform": {"x": 1.25, "y": 0.0, "z": -0.8, "yaw": 45.0},
      "state": {"fallen": false, "heldBy": null}
    }
  ]
}
```

- 首次进入旧世界时，仅对已存在的物品生成确定性初始布局，保持已有对象 ID；未明确定位的物品显示待摆放/默认布局，不凭空新增新的所有权、物品或生活经历。
- 任何移动、碰撞、掉落、拾起、开门、摆设变化都带原始 `entityId`、因果 `sourceEventId`、`before/after`、时间、结果状态；执行成功后持久化。重新进场时恢复同一状态。
- 模型可以建议“去看一下背后的东西”，不能直接伪造“东西掉了”；模拟物理决定是否真的掉落。由渲染器上报的本地物理事件先通过规则校验，才允许更新全局事实。
- 事实事件进入现有共同时间线；角色的惊讶/猜测进入主观状态，二者必须分开，删除源事件时依照现有失效规则清理派生记忆。

## 5. 三种摄影机

1. **见面自由镜头**：用户拖动环视，角色仍根据自己的目光目标行动；碰撞/遮挡避免镜头钻墙、穿人。
2. **自拍式虚拟视频通话**：角色持手机，角色手部 IK 约束手机位置，`SelfieCamera3D` 绑定手机前摄的实际变换矩阵。角色转手腕/转身展示房间时，用户看到的画面真的改变。前后镜头切换须先执行切换动作，不能只改背景图。
3. **固定手机视角**：角色把手机放在真实桌面/支架的可放置点，镜头随物品留在原位；角色离开画面、看向身后的声音、走去查看，取决于真实空间和声源。

视频通话第一版是**本机渲染的虚拟人物视频**，不是对方远程真实摄像头；不应要求用户开放自己的摄像头才能观看。是否要在本地显示用户摄像头是单独的权限与隐私需求。

## 6. 场景例子及严谨事件链

`object_fell`：
`physics_event(objectId, location, source)` → 检查是否有对象、物理是否可成立 → 写入位置与掉落结果 → 声音有真实源点 → 角色依据听觉范围/人格/当前行为分配注意力 → 动画 `turn_head` / `look_at` 或忽略 → 可能后续 `walk_to` / `inspect` → 回执写入时间线 → 对事件的情绪和回忆可能影响后来日记/朋友圈/群聊。

`show_room`：
角色提出想带用户看房间 → 查看是否在自己家/房间有什么真实物品 → 拿手机并进入 selfie 模式 → 转动实际镜头、指向真实 `itemId` → 讲述可核实的布置由来；还没有家具的地方必须真实空着。

`shy` / `show_off`：
心理驱动为表情和微动作提供权重与意图，环境决定可执行动作。害羞不必每次脸红和扭头；耍帅也不必统一摸头发。若角色此刻没兴趣表现，允许不执行。

## 7. 和已有 AI 人格、口语、日记的连接

`真实经历` → `多个不必一致的瞬时想法` → `自主权衡与选择` → `程序/物理执行` → `成功/失败回执` → `角色写日记/发朋友圈/发群聊或不说话` → `语义召回与证据验证` → `长期兴趣/习惯/个人表达风格逐渐改变`。

- 3D 情绪驱动与声音表现共用一次发言的总体情绪走向，视频不要出现上一句后悔、下一帧突然怒吼或切到夸张生气姿势。
- 日记/朋友圈是角色自己确实发表的**主观陈述**，不属于又新增一次世界经历；与单独记录的真实行为互相关联、但不互相冒充。
- 私聊可以轻快、碎碎念；朋友圈可以随手吐槽、适度熟悉的网络梗；日记可以有自问自答和标点留白；每人风格由个人人设、历史表达与真实文化接触塑造，不能统一网感。
- 如果角色真的学到新表达习惯，需要至少多个可靠情境与角色本人真实表达相互印证，不能因一句网络梗把人格统一改成网红主播。

## 8. 里程碑与验收

**阶段 0：嵌入与素材验证**
- 独立 Activity 可打开一间 3D 房间并返回原 App；载入一份**有合法使用许可**的 VRM 模型。
- 验证 Android 生命周期、屏幕旋转/回前台、声音并发、耳机切换、手势、安全内存与帧率。
- 只有该阶段验收通过，才向现有见面路由接入。

**阶段 1：动起来的角色**
- 眼球、眨眼、嘴型、表情 blendshape、呼吸、转头和自然过渡均受连续的情绪/语音状态驱动。
- 人设不同的角色，同样收到夸奖会出现不同反应，不强制复制动作。

**阶段 2：持久空间**
- 一房间多件真实家具，稳定 ID、三维位置、碰撞、放置/拾起和重启恢复。
- 做出“身后真实物品掉落→角色回头→判断是否检查→结果存档”的端到端用例。

**阶段 3：虚拟视频通话**
- 角色手持手机 / 固定手机两种机位；能够展示真实房间并用语音对话，不每句重设全部情绪。
- 呼叫、取消、切后台、回前台、耳机/扬声器切换与字幕正常。

**阶段 4：自主生活与社交**
- 角色可以自己改变场景里可行动的状态，出门、独处、串门、邀约、写日记或朋友圈。
- 伙伴相遇不要求用户在场；每种动作都能追溯真实事件 ID，不能用一张视觉动画代替世界记录。

## 9. 不要越过的质量红线

- 静态3D图或替换背景视频不等于拥有3D世界；模型“说转身”不等于动画真的转身。
- 角色头发和眼睛不应因插值/口型缺陷造成穿模或失真；交互前必须有可重现的物理与动画测试。
- 失败、取消、删除、旧存档迁移要能回滚；发生回执与说出口的话严格分离。
- 不保证任何具体机型帧率，真实 APK + 真机确认前都标记待验收。
