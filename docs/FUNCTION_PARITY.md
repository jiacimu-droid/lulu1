# Lulu 功能对等迁移清单

## 硬性原则

1. `lulu/master` 是功能基线，`lulu1/main` 必须达到功能零丢失。
2. UI、导航和页面视觉可以完全重做，但任何已有业务能力、数据、设置、玩法、历史记录、角色交互与失败路径都不能擅自删除。
3. 新增功能只能作为增量保留，不能替代旧功能。
4. 某个 App 只有在旧功能逐项核对、数据迁移、入口接入、主要交互可用且构建通过后，才能标记为“完整迁移”。
5. 未核对完成的模块必须标记为“部分迁移”或“待核对”，禁止使用“完整迁移”表述。

- 主动消息、提醒、承诺、责任与监督
- 插件及数字生活功能

## 验收状态定义

- **未迁移**：新仓库没有该能力。
- **部分迁移**：已有入口或部分规则，但不具备旧版完整能力。
- **功能对等**：旧功能、主要数据、入口和交互已保留。
- **增强完成**：在功能对等基础上增加新能力或重做 UI。
