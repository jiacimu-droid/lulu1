# 露露机：持续人格与经历驱动的成长框架

确认日期：2026-10-12。用户已确认采用此框架，后续逐步实现；文档描述目标，不能作为功能全部已实现的证明。

## 核心目标与平台

用户情感陪伴体验优先，当前重点私聊与电话；数字世界、阅读、日记、朋友圈共享同一角色。
手机持久保存人格、关系、经历、学习与任务状态，API按需承担理解、选择、表达与反思。不要求电脑或本地大模型，不声称更新API模型权重。

## 统一因果循环

真实感知 → 检索相关人格/关系/经历 → 理解与主观解释 → 情绪/想法/愿望 → 具体选择 → 实际表达或工具执行 → 真实回执/用户反馈 → 学习与修正 → 后续检索与应用。

- 想法必须有进入行动选择的入口；想做不等于已做，允许暂缓、放下与改变主意。
- 模型决定具体选择，程序校验对象/参数、执行、持久化、记录失败；不能从心声关键词直接强制动作。
- 重要愿望只写在心声而未选择动作时，给一次有真实能力与对象的后续判断；只有执行成功才能推进阅读/分享/探索状态。
- 原始感受与行动决策分开留痕；后续选择不能倒写或抹除原始动机。
- 阅读原文是文化接触，小说情节不是角色亲历；缺少材料和回执不能声称已学、已读或已分享。
- 在私聊、电话和数字世界保持同一记忆、关系、未解问题与相处偏好。

## 成长分层

1. 瞬时情绪/想法：随真实刺激和反馈变化，允许矛盾并存，不自动成为长期性格。
2. 用户明确偏好：原话、证据、适用情境；明确纠正立即影响后续互动，不机械等待多次重复。
3. 知识：来源、版本、理解、不确定性与纠错；与人格成长分离。
4. 技能/方法：实际尝试、结果、反馈、适用范围；写心得不等于学会。
5. 兴趣/习惯/表达：多次独立经历与反馈逐渐形成，能够修订，避免一次阅读永久换人格。
6. 核心人格/身份/价值：连续且变化谨慎，用户设置优先。

## 主动学习

自己的具体问题 → 真实材料 → 理解与疑问 → 延后复习/新情境应用 → 结果/反馈 → 修订或保留。
每条学习记录保存起因、来源、所学、未解问题、尝试、结果、反馈、适用情境。
角色可以继续、暂停或放下兴趣；是否分享、私聊/群聊/朋友圈由角色选择。不要固定每天百余节课，不交学习日报。

## 表达与体验

自然交谈是核心能力；长短、颜文字、表情包、网络梗、语气和分享随性格、情境与共同经历选择，不固定每轮添加。
行为变化应能在后续真实互动中感受到，不能只展示“成长记录”。
静默可能是懒得回应、忙或享受聆听，不机械认定用户已睡着、生气或离开。
哄睡支持连续长故事、身体放松、实际播放进度承接。
系统可靠性与相处能力分开：定时电话需要真实任务/回执，角色道歉不能代替调度修复。

## 手机与API实现原则

交互优先及时回应；后台整理/探索可批量合并，按用户预算配置。不对每句话串行调用多个模型。
按情境检索相关旧经历，不能只注入最近几条成长。更换模型尽量保留手机持久状态，但能力仍受底座模型影响。
删除原始证据须同步撤销派生记忆、学习和人格影响；重启恢复不补写虚假经历。
未运行/无网络/无真实新材料时，不声称持续学习。

## 2026-10-12：材料学习的首轮代码落地

- `CharacterLearningLedger` 从已提交的阅读进度、真实 `reading:` 证据派生主观理解、疑问、不确定性和适用情境；不创建第二人格档案，也不把主观理解冒充权威知识。
- 后续真实阅读可显式引用同主题旧证据修订理解；没有来源、证据已删或修订对象不匹配则拒绝。Full-context 网关按本轮问题召回最新有效理解，私聊、电话和主动生活共用且不新增 API 调用。
- 主动生活决策可选 `learningApplication`；成功执行并留下真实回执后，记录为一次“尝试应用”，不表示掌握技能或获得好评。删除阅读/回执会撤回关联投影，清空角色同时清理。
- 尚未实现用户反馈驱动的通用知识校正、跨渠道方法验证评分或自主上网课程体系。不得声称已经完成。

## 第二轮：跨场景的实践反馈、反证与自然表达（2026-10-12）

- 阅读学习记录继续复用同一证据链：修订必须指向同主题、时间更早且仍有效的阅读理解；原始材料被编辑/删除后，下游修订不会伪装成无来源知识。
- 私聊/电话的同轮决策可引用刚才真实用户评价 `learningFeedback`，只对应曾有真实执行证据的学习应用。用户原话、主观分类和执行回执分开；没有新 API 调用，不把好评自动升级成稳定习惯。删除用户原话时撤销对应评价。
- 同轮决策可选 `learningApplication`，文字真实送达或口语确实播放完成后才作为实践回执入库；尚未发出的规划与被取消的语音不算实践。
- 原始时间线里关于交流语气、说教、主动分享的明确反馈进入现有跨场景反馈上下文，不硬编码为所有角色都使用同一种表达风格。
- 尚须真机验证跨设备语音回执、完整电话收音与主动探索频率，以及多次跨日实践才形成的成熟方法。这里的记录不是训练底座权重。

## 第三轮：保留争议与展示真实成长轨迹（2026-10-12）

- 用户在真实私聊/电话里对某条已读材料理解提出明确反证时，同轮模型可提供 `learningChallenge` 关联阅读证据。系统只保存实际用户原话与存疑点，**不会**自动判定书、用户或模型谁正确，也不会擦除原理解。
- 原始反证删除后，学习投影和召回同步消失；同一条纠正不重复计为多个经历。
- 将阅读理解、实际应用、用户反馈及尚待核对的反证投影到现有成长轨迹。不以“想做”“道歉”“学会了”的生成文字制造假的完成记录。
- 真正持续学习和关系恢复仍以跨时空新证据与后续行为为准，不引入成长积分、强制阅读数量、额外监控或额外模型串行调用。

## 第四轮：持续愿望的阶段与归属（2026-10-12）

- 延用 `CharacterLifeStore.intention` 单一持续愿望槽，补考虑、已决定、执行中、失败待调整、行动成功待后续确认、暂缓和放下阶段，状态持久化且有用户设定之外的私有动机身份。
- `ToolRouter` 只在自主决策明确传入该愿望的 `intentionId` 时推进它；其他工具、拒绝执行和纯粹心声不再算入该愿望。独立的 `motiveId` 仍归内在动机系统。
- 成功工具回执不代表长期愿望完成、关系修复或用户满意。此轮不替代其他已有动机/任务体系，也不自动推断行为与意图相关性。
- 需要 APK、真机验证重启与并发执行。

## 本轮集中收尾：真实分享回执、自主探索复议及源删除（2026-10-12）

- 角色以往真实生活、疑问、未分享意愿加入下一次在线自主选择；不仅依据本轮临时心声判断有没有事情可做。每轮最多携带少量最新未解决线索，不增设定时配额，不代替角色做决定，也不因为用户沉默强制联系。
- 私聊/群聊真实已发消息、表情包、朋友圈本人发布的时间线证据成为分享成功的唯一入库依据；日常生活动作则需执行器的真实回执。原始记录删除后同步撤销被记作「已分享／已探索」的成果，但不消灭仍存在的原始生活经历。
- 原有工具路由为成功结果提供实际证据ID，直接社交行动尽可能返回被送达的原始消息/动态ID；聊天和电话的送达回执同样共用这个证据检查。已发布的动态不可仅凭模型文本宣布完成。
- 持续愿望处于 paused/executing 时不再误认为应不断复议的全新工作；失败、真实体验与候选兴趣仍给角色自行改变方向的机会。
- 这些是代码链路的收尾，不等于已验证角色会经常主动发圈，也不等于通话声学、耳机中断、世界内容丰富度和全部第三方模型表现已达到理想体验；需要最新 APK 自动测试和真机验证。

## 17项拟人框架代码审计追加修复（2026-10-12）

- 真实回执统一走 `CharacterActionEvidence`：群聊需本人专属事件，语音需真正写入聊天时间线，朋友圈需本人发布证据；阅读/游戏/数字生活必须有真实记录或成功工具结果。拒绝静默、纯观察和模型自称执行。
- 自主疑问先确认原始用户消息/系统观察确实存在；探索、学习应用和生活分享都校验同一类真实行为，不再用任意字符串 ID 宣告成功。
- 执行中暂停的愿望仍接受后来抵达的实际执行结果，但保留暂停状态；重启后若工具结果已经持久化，重复同一 requestId 会尝试补写缺失的原始工具回执/愿望投影，不重复执行副作用。
- 真实长程自由探索、外部材料可访问性、声音/耳机/STT 假唤醒、页面体验以及模型在不同人设下的自然表达，仍需要真机和多天实际使用验证；自动化通过不代表它们已经全部实现或达到理想体验。

## 17项复核补丁：长期相处偏好与实时通话上下文（2026-10-12）

- 用户明确表达的相处边界、语气和安全感反馈不因超过180天自动从人格上下文消失；同类反馈优先采用时间线上最近一条真实原话，删掉最近反馈后可依据仍在的旧原话恢复，避免一生只能发出同一种表达规则。
- 实时语音代理的角色核心上下文直接注入手机持久化的有来源阅读/方法尝试记录，不再仅靠普通聊天网关加载，允许换声线/服务但延续已形成的相处理解；仍不能将阅读等同于训练模型权重。
- 长时执行允许实际回执晚于在线判断的起始时间，不因一个固定60秒窗口丢失真实行动；每种动作仍须通过 `CharacterActionEvidence` 的来源验证。
- 不能根据本文件声称最新 Scribe Realtime 的收音、耳机播放以及静音打断已完成真机验证，也不能声称外部世界自由探索不依赖真实资源。

## 兼容性回归：真实阅读不是纯文本自报（2026-10-12）

- 新的 `read_book` 在阅读进度真正提交后，将 `reading:` 原始证据明确标为程序 `Observation`，不继续沿用泛化的 Legacy 类型。
- 旧版已经记录在权威阅读时间线里的 `reading:` Legacy 条目仍按真实已读记录兼容，能够进入好奇/学习尝试，不因新校验丢失历史；普通 Legacy 聊天文本与角色自报不能通过这种兼容通道。
- 增加旧版阅读兼容回归测试；“想读”仍不等于已完成读书进度。

## 落地顺序与验收

1. 用户反馈跨私聊/电话生效，修复收音及想法→实际行为断点。
2. 增加知识/技能学习记录、情境检索、应用与修正验证。
3. 完善自主探索、兴趣成长与自然分享。

验收：改变问法/场景/间隔后仍体现已学相处偏好；有真实材料与行为回执；反证能修正；删除与重启正确；未验证心得不会冒充技能。代码检查、自动化测试、APK构建与真机体验分别报告。

## 本轮具体通话要求

用户使用ElevenLabs Scribe v2 Realtime：思考和TTS合成尚未出声时，继续收音并允许确认的新话取代旧回复；真正开始播放后不打断，耳机也遵守此要求。实时音频不应被手机端音量VAD先行丢弃，轻声仍送Scribe；静音和实际播放时不采集成用户发言。
