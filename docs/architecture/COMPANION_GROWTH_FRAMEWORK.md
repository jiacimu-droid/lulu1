# 露露机：持续人格与经历驱动的成长框架

确认日期：2026-10-12。用户已确认采用此框架，后续逐步实现；文档描述目标，不能作为功能全部已实现的证明。

## 2026-10-20：独处小说不应反向定义用户

- 已写成的独处小说属于**文学正文**，只有原世界动作证据属于客观经历。不能把小说中对用户性格、态度、反应的未经证实猜想，当作后续人格、关系或记忆的证据。
- 写下一篇独处小说时，参考上一次核实的现实动作而不是上一次小说的叙事正文；统一人格上下文也仅承接独处原始行动，避免小说风格与未经证实的印象循环自我强化。
- 个人关系网络的本人→他人方向，允许显式撤回一条主观印象；撤回不删除真实聊天、相遇、世界行动、明确关系约定与其他人物的记录。
- 新篇章优先按已执行动作和本篇文学内容命名，首行提供独立散文式篇名，不再把活动计划名或「一段独处时光」当正式文章标题。
- 阅读页提供单篇删除和确认。删除只撤掉文学成果，同一原始动作的后续后台写作任务不可重新复活已删作品。具体主观印象是否存在于手机端要以本地关系状态为准，仓库源码无法推断。

## 2026-10-20：角色阅读与剧情解耦

- 角色读书消息不再展示旧独立阅读 App，直接定位小剧场中的原书原章节；点击章内被划线的句子查看评论，历史书籍与读后感不强制迁移和删除。
- 书架中的虚构内容是可读文化作品，不等于用户的心理自述、暗示或现实偏好。角色的第一反应应围绕剧情人物、冲突、台词和自己的审美感受展开；没有用户真实明确表达的个人意愿，不能由小说反推用户诉求，也不应把小说情节纳入关系挂心。
- 旧版不属于小剧场的阅读记录继续留在历史存储；没有匹配章节时回到小剧场书架，不伪造目标章节。实际 APK 编译和真机跳转需要单独验收。

## 2026-10-19：人物记录的正式归属（替代下文旧页面分工）

- 私聊菜单统一为「此刻／记忆／生活记录／日程／角色设置」。个人记忆与桌面记忆使用同一实现，只改变角色范围。
- 记忆只分「记住的事／原始时间线」。生活事实笔记与有来源的学习理解并入记住的事的只读投影，不复制、迁空或另造记忆库；配置、整理与注入诊断放管理抽屉。
- 此刻集中当前心情、心声、挂心、持续打算与进行中的行动；心声历史按时间合并原状态快照、真实选择、回执关联和当时的主观变化。历史锚点不能读取后来改写的挂心。
- 生活记录提供小剧场、日记、收藏、本人朋友圈的独立阅读入口，不承载生活事实、执行报告、学习或成长列表。正文仍由各自原 Store 保存；时间线和记忆引用来源。
- 日程承载本人活动安排、实际承诺任务和未定时旧约定。任务关联的旧词条不重复显示；原始回执继续留在时间线，不另外增加经历页。
- 人格页面的「经历形成的倾向」读取 CharacterRuntime 使用的同一有效 DevelopmentRecord，按兴趣、习惯、相处方式等展示当前变化及来源。短时感受留在此刻，已形成的知识留在记忆。学习配置归管理、当前学习问题归此刻。
- 学习理解的 UI 与统一记忆召回使用相同的有效来源／修订规则；实际应用、练习、质疑与用户反馈可在记忆详情追溯。原始来源删除后同步撤回理解和有效人物影响。
- 同一执行的原生事件与引用它的工具回执只算一次成长经历。日记、朋友圈和其他自述不能增加实际经历次数。保留原始 ID 和版本校验，不通过生成更多展示文字制造成长。
- 旧日记／收藏／小剧场链接保持锚点；旧历程链接转原始时间线，旧生活／关心笔记转记忆，旧约定链接转日程。移除正式历程 UI 及其重复的聚合器。
- 验证分开报告：本次回归覆盖归属、学习修订与撤回、统一召回、证据去重、状态历史与时间边界；Android 构建与真机显示仍分别验收。

## 核心目标与平台

用户情感陪伴体验优先，当前重点私聊与电话；数字世界、阅读、日记、朋友圈共享同一角色。
手机持久保存人格、关系、经历、学习与任务状态，API按需承担理解、选择、表达与反思。不要求电脑或本地大模型，不声称更新API模型权重。

## 统一因果循环

真实感知 → 检索相关人格/关系/经历 → 理解与主观解释 → 情绪/想法/愿望 → 具体选择 → 实际表达或工具执行 → 真实回执/用户反馈 → 学习与修正 → 后续检索与应用。

- 想法必须有进入行动选择的入口；想做不等于已做，允许暂缓、放下与改变主意。
- 模型决定具体选择，程序校验对象/参数、执行、持久化、记录失败；不能从心声关键词直接强制动作。
- 重要愿望只写在心声而未选择动作时，给一次有真实能力与对象的后续判断；只有执行成功才能推进阅读/分享/探索状态。
- 原始感受与行动决策分开留痕；后续选择不能倒写或抹除原始动机。
- 阅读原文是文化接触，小说情节不是角色亲历；缺少材料和回执不能声称已学、已读或已分享。
- 在私聊、电话和数字世界保持同一记忆、关系、未解问题与相处偏好。

## 2026-10-17：关闭页面后的后台陪伴

- 用户可关闭的 `specialUse` 常驻前台服务承接普通感知，独立于聊天 Activity 和通话麦克风；划掉最近任务不主动停止服务。仅到角色原定时间且联网时进入原有统一感知循环，不提高付费模型频率，不把自愿沉默变成失败。
- 普通感知同时登记非精确空闲唤醒和持久系统任务，十五分钟守护只核查是否到期。重启、覆盖安装、时区变更与实际重新打开应用恢复排程；不借用叫醒闹钟权限伪装普通感知。系统强行停止与厂商电池限制仍受 Android 管理，不能声称服务必定永不被杀。
- 感知在模型阶段与外部动作阶段分别落盘。模型请求中断保留一次四分钟延后恢复，受原有两小时冷却约束；动作期间中断不盲目重放，读取已有真实消息和工具回执。
- 实际角色消息先保存再统一通知，覆盖通用工具发私聊、群聊与表情等入口。当前可见会话不弹窗，静音群不响铃，通话转写和系统活动记录不作为聊天消息通知；同一回复的多个气泡更新一条通知。用户已关闭或自行调低的旧通知设置保持有效。
- 自动化回归与 APK 构建不代替用户手机上锁屏、清理最近任务、断网再联网后的接收验证。

## 成长分层

1. 瞬时情绪/想法：随真实刺激和反馈变化，允许矛盾并存，不自动成为长期性格。
2. 用户明确偏好：原话、证据、适用情境；明确纠正立即影响后续互动，不机械等待多次重复。
3. 知识：来源、版本、理解、不确定性与纠错；与人格成长分离。
4. 技能/方法：实际尝试、结果、反馈、适用范围；写心得不等于学会。
5. 兴趣/习惯/表达：多次独立经历与反馈逐渐形成，能够修订，避免一次阅读永久换人格。
6. 核心人格/身份/价值：连续且变化谨慎，用户设置优先。

## 主动学习

自己的具体问题 → 真实材料 → 理解与疑问 → 延后复习/新情境应用 → 结果/反馈 → 修订或保留。
每条学习记录保存起因、来源、所学、未解问题、尝试、结果、反馈、适用情境。
角色可以继续、暂停或放下兴趣；是否分享、私聊/群聊/朋友圈由角色选择。不要固定每天百余节课，不交学习日报。

## 表达与体验

自然交谈是核心能力；长短、颜文字、表情包、网络梗、语气和分享随性格、情境与共同经历选择，不固定每轮添加。
行为变化应能在后续真实互动中感受到，不能只展示“成长记录”。
静默可能是懒得回应、忙或享受聆听，不机械认定用户已睡着、生气或离开。
哄睡支持连续长故事、身体放松、实际播放进度承接。
系统可靠性与相处能力分开：定时电话需要真实任务/回执，角色道歉不能代替调度修复。

### 2026-10-18：私聊的说话对象、背景材料与内心交接

- 普通“上线后处理新消息”实际由 `ProactivePerceptionRuntime` 生成，聊天页旧 `sendAndReceive` 不是这个入口。仅同一私聊的真实用户未读消息时，将双方历史与当前原话放入同一次自主决策请求，并附本轮交谈目标和节奏；不为每轮另加表达模型。多场景同时未读时保留明确场景归属，不把群聊角色的话冒充用户原话。
- 决策仍使用统一人格、记忆和真实感知；表达阶段从当前私聊已保存的双方消息承接，用原始发送者确定 API 的 user/assistant 身份，当前用户消息独立放在最后。系统回执、撤回内容、失败草稿和其他角色发言不伪装成本人的聊天。无准确会话依据时沿用原有材料路径。
- 负面情绪不自动分派“让对方安心／劝她休息”的任务。表达接收已选核心立场、必要答案、当下感受与不确定性，不重复交接整包内心、心理归因和关系分析；稳定身份、称呼与核心记忆仍由统一网关注入。
- 私聊表达指令精简为接着本人对话说话、按场景取舍内容和完整返回正文结构。历史发言保留事实，不把旧长篇或通用示例当成所有角色的语言标准。自然度检查只允许既有的一次模型改稿，不能按字数裁掉正文；选择改稿仍保护执行失败、否定、数值和链接。详细问题、创作与哄睡不套普通短回复节奏。
- 参考 [SillyTavern 的提示词与历史影响说明](https://docs.sillytavern.app/usage/prompts/)、[AIRI 的消息角色投影](https://github.com/moeru-ai/airi/blob/266e8d9467197f9562279d6291eddae758b11fe2/packages/core-agent/src/messages/render-provider-chat.ts) 和 [MaiBot 的实际回复请求组装](https://github.com/Mai-with-u/MaiBot/blob/ac6ed61b7b9c971ad94921de3b16fa6f63c36a20/src/chat/replyer/maisaka_generator_base.py)，借鉴上下文组织，不宣称它们的提示词适合所有人物或模型。固定响应的接口测试只能证明发送、选稿与兼容链路；自然度仍需当前模型的真实多轮输出验证，APK 构建不能代替这项验收。

### 2026-10-17：后台叫醒与恢复竞态

- 精确系统闹钟从冷进程启动独立短前台服务，维持执行与最多两分钟的待接听；不借用上一晚的麦克风通话服务。持久化 WorkManager 任务作为调度兜底，两条路径只能消费一次本机凭据。
- 页面恢复不再抹掉刚到点的闹钟，也不把同进程仍在执行的约定判为中断。实际系统/补偿触发时间、来源与计划时间分开持久保存，短暂延迟如实显示；超过两分钟的旧任务不补拨、不冒充准时完成。
- 静默结果复查在获准时同样使用精确定时；重启、覆盖安装、时间变化和重新授予精确闹钟权限后重挂尚有效的任务。冷启动也会建立来电通知渠道；锁屏全屏权限可在既有人格授权区管理。
- 自动化回归覆盖冷进程来电、恢复与执行并发、重复投递、取消、旧回调和持久化。完整 APK 构建与具体手机锁屏/厂商后台限制仍需分别核验，不能用构建通过证明真机准点来电。

## 手机与API实现原则

交互优先及时回应；后台整理/探索可批量合并，按用户预算配置。不对每句话串行调用多个模型。
按情境检索相关旧经历，不能只注入最近几条成长。更换模型尽量保留手机持久状态，但能力仍受底座模型影响。
删除原始证据须同步撤销派生记忆、学习和人格影响；重启恢复不补写虚假经历。
未运行/无网络/无真实新材料时，不声称持续学习。

## 2026-10-12：材料学习的首轮代码落地

- `CharacterLearningLedger` 从已提交的阅读进度、真实 `reading:` 证据派生主观理解、疑问、不确定性和适用情境；不创建第二人格档案，也不把主观理解冒充权威知识。
- 后续真实阅读可显式引用同主题旧证据修订理解；没有来源、证据已删或修订对象不匹配则拒绝。Full-context 网关按本轮问题召回最新有效理解，私聊、电话和主动生活共用且不新增 API 调用。
- 主动生活决策可选 `learningApplication`；成功执行并留下真实回执后，记录为一次“尝试应用”，不表示掌握技能或获得好评。删除阅读/回执会撤回关联投影，清空角色同时清理。
- 尚未实现用户反馈驱动的通用知识校正、跨渠道方法验证评分或自主上网课程体系。不得声称已经完成。

## 第二轮：跨场景的实践反馈、反证与自然表达（2026-10-12）

- 阅读学习记录继续复用同一证据链：修订必须指向同主题、时间更早且仍有效的阅读理解；原始材料被编辑/删除后，下游修订不会伪装成无来源知识。
- 私聊/电话的同轮决策可引用刚才真实用户评价 `learningFeedback`，只对应曾有真实执行证据的学习应用。用户原话、主观分类和执行回执分开；没有新 API 调用，不把好评自动升级成稳定习惯。删除用户原话时撤销对应评价。
- 同轮决策可选 `learningApplication`，文字真实送达或口语确实播放完成后才作为实践回执入库；尚未发出的规划与被取消的语音不算实践。
- 原始时间线里关于交流语气、说教、主动分享的明确反馈进入现有跨场景反馈上下文，不硬编码为所有角色都使用同一种表达风格。
- 尚须真机验证跨设备语音回执、完整电话收音与主动探索频率，以及多次跨日实践才形成的成熟方法。这里的记录不是训练底座权重。

## 第三轮：保留争议与展示真实成长轨迹（2026-10-12）

- 用户在真实私聊/电话里对某条已读材料理解提出明确反证时，同轮模型可提供 `learningChallenge` 关联阅读证据。系统只保存实际用户原话与存疑点，**不会**自动判定书、用户或模型谁正确，也不会擦除原理解。
- 原始反证删除后，学习投影和召回同步消失；同一条纠正不重复计为多个经历。
- 将阅读理解、实际应用、用户反馈及尚待核对的反证投影到现有成长轨迹。不以“想做”“道歉”“学会了”的生成文字制造假的完成记录。
- 真正持续学习和关系恢复仍以跨时空新证据与后续行为为准，不引入成长积分、强制阅读数量、额外监控或额外模型串行调用。

## 第四轮：持续愿望的阶段与归属（2026-10-12）

- 延用 `CharacterLifeStore.intention` 单一持续愿望槽，补考虑、已决定、执行中、失败待调整、行动成功待后续确认、暂缓和放下阶段，状态持久化且有用户设定之外的私有动机身份。
- `ToolRouter` 只在自主决策明确传入该愿望的 `intentionId` 时推进它；其他工具、拒绝执行和纯粹心声不再算入该愿望。独立的 `motiveId` 仍归内在动机系统。
- 成功工具回执不代表长期愿望完成、关系修复或用户满意。此轮不替代其他已有动机/任务体系，也不自动推断行为与意图相关性。
- 需要 APK、真机验证重启与并发执行。

## 本轮集中收尾：真实分享回执、自主探索复议及源删除（2026-10-12）

- 角色以往真实生活、疑问、未分享意愿加入下一次在线自主选择；不仅依据本轮临时心声判断有没有事情可做。每轮最多携带少量最新未解决线索，不增设定时配额，不代替角色做决定，也不因为用户沉默强制联系。
- 私聊/群聊真实已发消息、表情包、朋友圈本人发布的时间线证据成为分享成功的唯一入库依据；日常生活动作则需执行器的真实回执。原始记录删除后同步撤销被记作「已分享／已探索」的成果，但不消灭仍存在的原始生活经历。
- 原有工具路由为成功结果提供实际证据ID，直接社交行动尽可能返回被送达的原始消息/动态ID；聊天和电话的送达回执同样共用这个证据检查。已发布的动态不可仅凭模型文本宣布完成。
- 持续愿望处于 paused/executing 时不再误认为应不断复议的全新工作；失败、真实体验与候选兴趣仍给角色自行改变方向的机会。
- 这些是代码链路的收尾，不等于已验证角色会经常主动发圈，也不等于通话声学、耳机中断、世界内容丰富度和全部第三方模型表现已达到理想体验；需要最新 APK 自动测试和真机验证。

- 已提交的数字世界动作立即给出真实结果；独处正文进入持久后台写作，不占用感知锁。正文引用执行时的物件快照，提交时原始事件必须仍存在且修订未变。删除、改写或清空来源后的迟到正文不能重新进入记录和上下文。
- 新的 innerLife.motives.reviewAfter 接入持久复查；按实际 motiveId 和计划指纹校验，暂停、释放、改期和重复投递不会复查旧计划。到期只提供一次本人选择机会；同时到期的多个目标合并一次感知，尊重安静时段与当前用户消息/电话，过时复查不补做无依据的联系。
- 电话中的明确小红书请求保存为持久任务，绑定真实用户原话及其修订。同一条请求不重复阅读；原话删除后不回填旧结果。实际回执先保存到原私聊，当前通话空闲时可由同一角色继续理解和表达；不会打断双方的发言、伪造新用户语音或把旧结果带进另一通电话。原通话结束后仍沿统一时间线使用真实回执。
- 普通人物的表达渲染、改稿和 CharacterAndScenario 调用保留适用的全局及本人世界书；独立剧场和跨世界作品继续隔离。删除 API 配置同时清除其模型存档，构建版本与提交号显示于设置。
- 群消息删除传播到当时的全部见证成员；整群删除使用稳定会话归属，避免同名群串删。新增成员与群电话事件保存 conversationId；无法确定归属的旧群电话不能仅凭同名扩大删除。清空一个角色保留其他参与者的共同见面和原话，移除本人的主观快照；较长见面和独处历史不再按固定条数静默裁掉。
