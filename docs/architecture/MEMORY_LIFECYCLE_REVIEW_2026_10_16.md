# 角色记录、记忆与此刻：职责审计和统一循环方案

日期：2026-10-16。审计基线：`a3279a4966c229ca768c761ad8d514f92897e3bf`。

状态：原始审计与建议方案，后续实现见文末。审计章节描述的是基线状态；当前改造复用原始 Store，不安装第三方记忆服务，也不表示完整时态图谱已实现。

## 一、用户真正提出的问题

1. 角色设置、此刻、辞海、记忆的职责是什么，能否收成三个主要入口？
2. 每天新增的心声、挂心、愿望、日记、收藏、成长记录是否全部进入每次模型请求？
3. 如何让新增、更新、召回、行动、反馈、整理与删除形成同一循环？
4. 采用值得借鉴的开源机制，保持模型负责语义理解，程序负责数据一致性与执行，不把例子固化成角色反应规则。

## 二、目前四类功能的真实分工

| 功能 | 当前正式入口/实现 | 数据用途 | 目前的交叉 |
| --- | --- | --- | --- |
| 角色设置 | `CharacterSettingsScreenV2`、`CharacterLifeSettings` | 身份、用户设置的人格、稳定倾向、称呼、陪伴和管理配置 | 成长与学习过程也放在设置页；配置与经历的浏览职责混在一起 |
| 此刻 | `CompanionPresenceDialog` | 最新状态、心声、想法与行动、仍在意的事情、历史心声 | 瞬时状态与持续愿望同屏；与辞海挂心、成长叙事有概念交叉 |
| 辞海 | `LexiconFeatureScreenV2` | 生活/挂心、约定、日记、收藏、历程，以及真实任务的视图 | 已包含可召回内容和成长/行动轨迹，并非单纯手写笔记 |
| 记忆 | `MemoryFeatureScreen` | 核心、长期事实、情绪印象、重要经历、待整理，以及自动整理与召回控制 | 与辞海共同保存经历的不同表达，但目前是两个管理入口 |

这些页面不能简单理解为四个独立记忆库。部分条目来自不同持久化 Store，部分页面已经是任务、心理状态或时间线的投影；减少入口不应再复制数据。

源码中私聊菜单当前提供角色设置、辞海、记忆与角色世界书；此刻还可从头像进入。三个主要功能区的方案不等于删除世界书、头像快捷入口或旧导航。

## 三、推荐三个主要入口

| 入口 | 回答的问题 | 包含内容 |
| --- | --- | --- |
| 角色 | 他是谁、怎样相处、如何配置 | 资料、稳定人格、称呼与关系偏好、表达/声音设置、陪伴权限、世界书及管理 |
| 此刻 | 他现在怎样、什么仍在影响他 | 当前情绪、未出口念头、持续愿望、未解挂心、当前行动；历史心声作为可展开的历史 |
| 记忆 | 发生过什么、记住什么、答应什么、学到了什么 | 核心与往事、约定、日记与收藏、成长历程；设置保留入口，但学习过程和成长证据以这里为主要浏览位置 |

辞海与记忆合并的是信息入口和检索体验，不是把所有内容混成一种 MemoryEntry。日记、收藏、真实约定、模型理解与稳定人格仍有不同语义和更新规则。

迁移应复用原有 ID、来源、时间、状态与编辑/删除入口。旧辞海/核心记忆/阅读通知链接继续能定位到原记录。角色维度保持隔离；独立剧场和末世记忆的既有边界保留。

若仍保留四个入口，以下后台循环同样成立；页面数量不决定模型拿到多少上下文。

## 四、现在每轮究竟会注入什么

关键链路：`CompanionModelGateway.generate` → `CharacterRuntime.memory` → `UnifiedMemoryOrchestrator.assemble`，再分别拼接人格、当前状态、成长/学习、连续性、世界状态、核心、召回摘要、原始证据与辞海。

| 类别 | 当前行为 | 需要注意 |
| --- | --- | --- |
| 身份和稳定设定 | 按场景模式读取当前用户设置 | 与过去生成的台词和短期情绪区分 |
| 核心记忆 | 有效来源的核心记录走独立常驻通道 | 当前不是普通召回预算内的少量结果，持续增加仍可能撑大输入 |
| 普通长期记忆 | 按查询召回并受数量、字数和来源有效性约束 | 保存了不等于本轮一定选中；当前原话可优先于摘要 |
| 近期原始经历 | 根据个人规则选择有限近期窗口，再按字数呈现 | 未整理积压由持久化队列处理，不会全部复制进每轮请求 |
| 此刻状态和心理记录 | 当前感受、近期念头、动机等按紧凑/丰富模式呈现 | 不是整个心声历史；丰富模式的一些列表仍可能较长 |
| 成长和已读理解 | 按当前话题选取已有成长/学习记录 | 展示的成长历程不等于每次注入整段历程 |
| 辞海 | 活跃挂心/生活/约定优先，加上相关日记/收藏，再受展示预算约束 | 候选选择与最终注入存在两层限制，前面的活跃条目可能挤占后面的相关内容 |
| 未完成责任 | 多条链路单独提供，避免失约和靠模糊回忆执行 | 同一任务可能在统一记忆、责任事实及聊天决策素材中重复出现 |

例如普通请求的现有预算包括记忆摘要 4000、原始证据 1200、近期时间线 2600、辞海 1500 **字符**；精确核对、世界交互、自主感知等场景会增加额度。这些是代码中的局部字符预算，不是整轮 token 总上限，也不是每次请求的固定实际用量。

私聊的表达步骤有轻量交接路径；它与做决定的主模型不是同一个上下文需求。电话、群聊及独立任务也有自己的模式，不能笼统说每个 API 请求都会拿到以上全部项目。

## 五、已经有的能力和缺口

已有：统一原始时间线、来源检查、近期窗口、语义/本地召回、核心通道、记忆维护合并、Fact 之间的模型替代判断、提取队列与重启重试、即时心理/愿望更新、约定真实执行、部分召回/注入记录。

尚未形成完整统一机制：

1. 各模块最终合并后的全局预算与跨类别去重。
2. 所有类别共用的有效期、来源版本和脏状态传播；Fact 替代不是整个角色记录系统的通用更新协议。
3. 统一的增量整理调度，避免多个观察器对同一新增经历重复提取或反思。
4. 有明确覆盖范围、证据和新鲜度的当前理解摘要；新纠正不能被旧摘要挡住。
5. 面向用户的一处记录管理与完整的“本轮为什么读到/没读到”说明。目前已有局部审计，不应新建一套重复监控。

## 六、统一生命周期

### 1. 原始经历先保存

保存谁、何时、何地/会话、看到或执行了什么。用户原话、角色台词、主观理解与工具真实回执保留各自证据类型。原话和执行回执是依据，日记与心声不是第二份客观事实。

### 2. 同一个角色模型理解语义并提出变化

沿用既有主决策中的思想、动机、挂心与约定字段，理解整段话及指代。以新增、修订、暂缓、结束或无需变化表达结果。程序校验角色归属、原 ID、来源、版本和可执行参数，不用固定词表代替理解。

### 3. 按职责更新现有记录

- 瞬时感受进入此刻，可随时间衰减；不自动重写核心人格。
- 同一挂心、愿望或约定修订原 ID；一次回应的多个气泡不应产生多份同义记录。
- 事实、偏好发生变化时标记新的当前版本；旧版保留为当时的历史，不能继续当成现在的事实。
- 已承担的责任交给持久任务/时钟系统；到期执行不依赖它恰好被聊天召回。
- 成长记录保存尝试与反馈；主观写下“学会了”不等于已经掌握。经过后续实践确认的方法才影响更稳定的行为倾向。

### 4. 后台合并与形成当前理解

按角色和发生变化的主题合并待处理工作，复用已有队列和证据索引。没有新材料、纠正或有效反馈时不重做同一份总结；失败保留重试位置，不把失败视为已经整理。

对确实值得长期维护的问题，维护一份带版本和来源范围的当前理解，例如“目前相处中有哪些已确认偏好”“这件未结事情进展到哪里”。优先增量修改受影响部分，避免每次让模型重写整个人格。它是可重建的派生视图，不是新的独立人格或另一个事实库。

这项整理不应阻塞聊天。新原话和明确纠正立即可用；摘要比来源旧时，召回同时带入新增/纠正的原始证据，不能盲信旧摘要。

### 5. 每轮组装一个有预算的工作上下文

统一在既有网关处组装，不让页面自己决定模型知道什么。依次保护当前输入与必要现场、稳定身份/必要核心、相关当前状态与未结事项，再为经历、成长方法和文化接触分配弹性预算。

候选综合相关性、重要性、时间、有效性、当前未结程度和来源多样性；不是只取最新、只做向量相似度或把全部待办强塞每句话。核心过长时应显式整理和版本化，不能静默截断用户指定的重要事实。

同一事实被摘要、日记、成长记录和辞海引用时，按原始来源识别重叠；事实只提供一次，不同的主观解释可以保留并明确归属。按场景选择不同信息，但共享同一当前版本。

沿用现有 token 分项与注入审计，补齐各类记录的选中原因、遗漏原因和来源版本；实际 token 与字符估算分开呈现，不另加每句付费的“上下文评审模型”。

### 6. 行动与反馈回到同一循环

实际表达送达、真实阅读、来电/闹钟和用户反馈形成新的事件，再修订原愿望、挂心、任务与经验。沉默或没有回执不能自动证明成功，写日记不等于执行了计划。

### 7. 删除和编辑逆向传播

编辑/删除来源后，相关索引、摘要、派生心事、成长证据、注入候选与缓存失效；新的后台结果落库前重查来源版本，避免删后复活。已经真实发生的动作及其独立回执，不因某条主观解读改变就伪装成没发生。

## 八、实施顺序和验收

1. 入口与数据职责整合：三个主要功能区，保留所有数据、旧链接、角色隔离和原编辑能力；世界书、学习预算等配置留在角色设置，成长经历集中浏览。
2. 上下文汇总：先去重职责记录，建立统一工作集与整体预算，扩展现有注入记录；核心与当前纠正优先，不凭硬截断牺牲事实。
3. 整理与版本：合并主题脏任务，增加当前理解的新鲜度和增量修订，复用原始来源/失效机制。
4. 跨日实践：检验召回是否真的改变行为，反证能否修订方法，已结束心事是否仍被反复带入；需要实际模型和真机观察。

必须覆盖的回归：同一件事不重复注入；新纠正先于旧摘要；多个气泡不累计为多次成长；持续监督无固定时刻仍存在；改期沿用原任务；过去感受不冒充现在；删除与在途写入竞争后不会复活；换场景仍是同一角色；独立故事记忆不串入角色生活；大量记录时工作上下文仍受预算约束。

本轮只读审计及文档静态校验不等于上述改造的测试通过，也不等于已发布新的 APK。


## 九、本轮代码实现（2026-10-16）

- 三个主要入口：角色设置、此刻、记忆。旧辞海路由及日记定位链接进入同一记忆容器的「生活记录」，沿用原始编辑、删除、角色隔离及记录 ID；「学习与成长」显示原学习目标和证据，学习额度继续在设置。
- `MemoryWorkingSet` 在 Full 模型网关统一选择近期原话、原始依据、摘要、生活记录、当前状态、连续性和学习/成长。普通记忆工作集为 12000 字符，丰富场景 19000、精确核对 23000；这不是整个 API 输入/token 上限。身份、世界书、用户本轮输入和可执行世界清单独立保留。常驻核心及未结责任完整保留并占预算，超额会在原检查面板明确说明；不会静默截断核心。
- 原话完整出现时不再重复其派生摘要；任务关联词条由真实 TaskStore 提供一次，日记、挂心、收藏的主观解释仍保留归属。不同事实即使引用同一事件也不互相排斥，否定词不被模糊去重。既有注入检查记录实际选中项、未选原因及预算。
- 原始时间线统一触发记忆自动整理；不再由聊天观察器另开提取。按角色合并持久化脏任务、带版本完成水位、继承失败退避、重启恢复；在途新增事件保留下一轮，删除最新来源不丢掉其他积压。没有新材料时不重复付费总结。日记/挂心的语义抽取和成长反思仍由各自原有职责模块负责，不声称全部提取器合为一个模型。
- 记忆与生活记录保存来源版本；提取提交、程序写入和向量写入重查原始依据，时间线改删与提取提交共用边界。编辑/删除立即撤回相关记忆、生活记录、学习、成长及心理投影；旧格式无版本字段可继续读取，后续改删仍同步撤回。用户编辑与后台生活记录更新用乐观校验防止相互覆盖。
- 沿用 MemoryValidityStore：同一次提取对比有预算的已有理解，可返回明确替代 ID，旧事实留作档案、从当前召回失效；主题类似、暂时情绪不自动替代事实。未提供新字段的兼容输出仍走原有替代检查。不创建新的人格/事实数据库。
- 自动化覆盖：新原话的预算优先级、原文/摘要去重及主观区分、大量记录预算、队列水位与重启退避、源版本变动与迟到写入、提取期间编辑、同轮当前理解替代。真机页面与跨日自主行为需要安装此轮 APK 后继续观察，不能以源码检查冒充验证。

追加收口：共同游戏与番茄钟的直接记忆也绑定原始事件和来源版本；番茄钟结算只保存计时事实，不再复制私聊全文。程序写入改用禁止自动恢复的 upsert，持久化按角色的已删除 ID，自动统计即使改变措辞也不能恢复用户删掉的同一记录；用户在编辑器明确恢复仍可保存。后台来源巡检只撤回仍等于待检查快照的旧条目，避免误删刚保存的新版本。
