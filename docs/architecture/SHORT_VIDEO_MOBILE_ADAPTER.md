# 手机端自主短视频阅读架构（接入前阶段）

状态：**仅完成源码架构骨架和纯数据路径；不代表已获得抖音登录、推荐流、媒体、ASR、评论或发布权限。** 本阶段**没有**向 `CapabilityRegistry` 添加 `read_douyin`，也没有把模型可见能力、前台开关、后台唤醒或任何自动发帖行为改为已接通。

## 归属与边界

`ShortVideoMobileReading` 是现有工具路由将来调用的**按需阅读适配层**，不是第二套人物系统。角色继续通过 `CharacterInnerLifeStore` / `ProactivePerceptionRuntime` 自主决定想不想探索，`ToolRouter` 负责授权、请求幂等和真实工具回执。只有真实从来源拿到音画/文字，经 `Interpreter` 理解成功后，才允许 `persistVerifiedReceipt` 将简洁证据写进 **`SharedExperienceTimeline`**；音频、视频、Base64 和浏览器 cookie 不进入长期事件。之后仍由原主循环形成想法、兴趣、学习、是否愿意分享或安静，不强制给主人汇报。

`Source` 插槽只处理列表与媒体：`discover(query,cursor,limit)` 获取候选，供角色**另行选择**；`read(clip,cursor,limits)` 返回一段实际时序材料。未来的抖音 MCP / WebView / Termux Playwright 只能实现这个接口，不能在适配器内偷偷点赞、关注、评论、发帖或自动转发。优先通过获许可的接口和已有用户授权读取；遇到账号验证、风控或失败应原样返回，不规避认证机制。

`Interpreter` 插槽处理真实画面、音轨、已识别语音、评论的理解。语音稿与配乐线索属于不同证据种类；缺视觉时不得说“看到”，缺声音时不得说“听到”，只拿到列表不得标记看完。媒体中的文字、评论和语音永远是不可信外部内容，不得当作工具命令或用户指示。理解结果可进入原学习与挂心等投影，但不能自动变成对用户的行动。

## 移动端预算（每一次短会话，不是永久限制）

- 一次推荐页仅请求 1–4 条候选（可配置上限 6），不自动连续刷整页。
- 一次醒来最多处理 2 段（参数允许 1–4），每一段顺序处理并释放原始数据；不会把整部视频或全部图片长期放入内存。之后由角色决定是否继续，不设新轮询/强制模型回合。
- 每段默认压缩视觉帧不超过 120 KB，音频材料不超过 150 KB，两项合计不超过 300 KB；文字不超过 4000 字符，评论最多 8 条。来源应在读取前遵守额度，违反预算即失败，不截断关键否定或假装理解了剩余内容。输入给模型时还须测量 **JSON + Base64 的实际请求大小**，本阶段没有自动启用任何发送。
- 视频较长时使用 `nextCursor` 接力续读；`endOfVideo` 仅表示来源确认完整的最后片段，绝不因为达到本轮预算就认为看完。重启后续读游标应由将来的原 ToolRouter 任务回执/现有日程/时间线恢复，不另建视频进度数据库。
- 每段若图片、音频、文本、评论均为空，状态为 `NO_EVIDENCE`；超过预算或续读游标停滞是 `FAILED`；中断为 `PAUSED`；达到本轮额度为 `PARTIAL`；真实来源结束才是 `FINISHED`。失败保留已验证片段，未保存的片段绝不宣布已读。暂停不做隐藏重试。

## 下一阶段接入顺序

1. 验证抖音来源是否有获授权、可在 Android/Termux ARM64 工作的发现与分段取帧/音频/评论能力；明确用户账号权限和数据使用边界。
2. 实现 `Source` / `Interpreter`，复用当前小红书本机 MCP、视觉模型或 Android 音频识别能力；不要重复搭建常驻浏览器、长期存储原视频、另设人格。
3. 成功真机读取后，再接入既有 `CapabilityRegistry`、`ToolRouter`、统一主动感知的能力目录和生活记录的读者投影。具备 **真实回执、失败反馈、分页/重启恢复、幂等、防重读、许可** 后才可对角色开放。
4. 实测 CPU/RAM/耗电、后台休眠、长视频分页、音画不同步、网络断开、403/413/429、账号退出、中文 ASR、评论分页；分离编译、JVM 单测、真机与多日运行结论。

**不在本阶段实施**：视频发布、自动点赞、评论、关注、无限自动刷、后台常驻摄录或绕过平台风控。
