# Jev 怎样用于露露机

核对日期：2026-10-26。目标是让角色自己把多个想法方向分别问一遍，再由本人解释和选择。此版提供可选原生API工具；不是自动给每轮聊天追加一次判断，也不把概率变成人格、用户情绪或行动命令。

## 主人只需配置一次

1. 在官方 https://console.typesafe.ai 创建密钥。当前环境没有主人手机里的密钥，本次没有代注册、充值或进行真实收费推理。
2. 露露机 → 设置 → API设置，保存TypeSafe配置：地址 `https://api.typesafe.ai/v1`，填写自己的密钥，获取模型并加入存档。建议先使用明确版本 `jev-1.14.0`，便于对比效果；实际可用型号以账户返回为准。
3. 同页“模型分工 → 多方向参考 · Jev”选择这个存档。没有选择时未启用；可以随时关闭。聊天、电话的原思考模型不会因此换成Jev。
4. 若确实需要把超过默认单题上下文的材料一次提交，可显式打开“Jev长上下文”；默认关闭。启用后不是必须发送全部历史，角色仍应选择相关材料，长期原文照常保留。

独立文字表达也在“模型分工”中选择。它只替换现有表达阶段，关闭后跟随本轮原模型；单次直接发言的在线私聊不因此增加第二轮润色。

## 角色怎样使用

原角色决定 → 选择 `consider_directions` → ToolRouter权限/幂等检查 → 一次TypeSafe原生请求 → 保存实际回执与用量 → 原角色收到全部问题和概率 → 本人继续理解、记录真正的新想法、选择0/1/N个行动。

- `state`：本人选取的相关原话、事实、人格、关系、旧经历或目前疑问；注明来源和猜测。不会由程序按词表替用户补写情绪。
- `questions`：本人提出的多个是否问题，各自起ID；本期接入 `noul`。每道题可写清楚怎样算是/否。方向由本人决定，没有“所有角色必想的十件事”或固定赚钱、恋爱、分享阈值。
- 返回 `directions`：每道原问题及其概率全部保留，含低概率和互相矛盾的可能。它们都是模型参考，不是已发生的事实、本人最终愿望或完成证据。
- 结果回流复用原工具后感知，不新建人格/想法库、不按最大概率选工具。不新增每轮固定请求；同一执行ID重放复用原回执，不重复请求。
- 缺回答、概率格式无效、HTTP失败均留失败结果，不拿聊天模型自动补做一次付费判断。关闭配置期间返回的迟到结果不再提交为可用参考，已经发生的正常API用量仍记录。

例如可以分别考虑“我对某个旧问题是否仍好奇”“某段经历是否与当前疑问有关”“这个尝试是否符合我目前的目标”。这是说明用法，不是统一角色的固定思考清单；赚钱、陪伴、独处或交朋友均由本人人格与真实经历决定。

## 接口与费用边界

官方入口是 `POST https://api.typesafe.ai/v1/systemone`，不是OpenAI的 `/chat/completions`。认证为Bearer；原生请求包含 `model/state/questions`。获取型号用同站点 `/v1/models`，现有设置页兼容其 `models[].name` 列表。

按2026-10-26官方模型页，Jev1.14输入价为 **$0.042/百万token**，输出免费。公式为“服务报告的input_tokens÷1,000,000×0.042美元”。若一次实际计费输入为60,000token，则为 **$0.00252**；这不是整条人物决策链总价，后续原角色模型继续思考的调用另计，中转价和换汇也另算。没有拿“每道问题重复发送整段历史”的方式实现。

默认限制为整包64k、state加任一道题32k；显式长上下文头将两者提高到262k，官方提示其可能更慢、准确率下降。服务端实际token校验是准绳；程序不按字符数猜token并静默截掉材料。官方另有32MiB请求体上限，超限在上传前拒绝。真实服务用量和实际返回型号进入原token统计；不伪造输入token。
