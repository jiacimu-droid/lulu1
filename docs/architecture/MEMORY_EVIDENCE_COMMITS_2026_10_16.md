# 记忆写入、整理租约与召回预算的补齐

2026-10-16，基于 main `7b8afcbe` 的统一工作集、来源版本与记忆页面继续修改；没有替换现有架构或添加外部记忆服务。

- 提取使用输入时的完整事件快照。模型返回后，整批上下文（含未被结果直接引用的邻近消息）必须仍一致，才能在时间线编辑/删除共用的锁内提交。任一上下文改变则整批拒收，保留整理位置，通过既有持久队列重试，不在同一次调用里无上限重新请求。
- 解析依据输入快照，不从模型结果中悄悄丢掉失效来源后保存残缺证据。陌生、跨批次或超过六条的来源拒收。来源 ID 查询按 SQLite 安全批量拆分，不再截掉第 121 条以后的校验对象。
- 沿用每角色一个整理任务和一个后台工作线程。新任务生命周期有独立 ID；完成/失败都可绑定原修订号，迟到的结果不能清掉新任务或污染新任务的重试状态。源删除保留角色的其他积压并撤回旧完成租约；失败退避不因新增消息清零。
- 召回候选与最终注入分开。不能因为原话在“近期候选”里就提前删掉摘要；最终统一工作集仅在原话完整且实际入选后去重。输入素材去重检查完整规范化文本，避免仅匹配开头就漏掉后面的更正。相关日记与活跃挂心交替进入候选顺序，共享原有预算；保留主观解释。历史情绪明确标注为当时状态。
- `digital_world` 的动作标识统一清理空白和 Unicode 格式字符，仍通过原有动作、地点和活动 ID 验证。截图不足以确定旧错误来自版本差异还是不可见字符，不能据截图宣称根因已完全确认。
- 执行器返回失败时，ToolRouter 同步写入现有统一错误日志，包含角色、能力、执行 ID 和实际失败内容；同一执行 ID 的重放复用既有结果，不重复记错。此刻的失败显示保留。

验证覆盖：邻近上下文被编辑、连续批次的处理位置、来源删除、超过 120 条来源、重启与失败退避、旧任务完成的 ABA 冲突、同请求语义修订、相关日记不被大量挂心挤走、情绪历史、真实地点活动及统一错误日志。完整 Android 测试与 APK 由现有发布流程核验；这些回归不能替代真实模型的长期相处体验。
