# Live2D 普通聊天表现

## 2026-10-29 正式演进：同一份分段表演

公共身体执行能力不改变任何人物人设、关系或心理 Store。已显示成功的视频 reply 使用同一次本人模型选择的 `speech`，台词、字幕、动作共享片段编号；不再依赖原文锚点查找。纯语音、哄睡长段与旧版输出继续兼容。下文旧语义参数协议仅作历史兼容，不能盖过真实 Motion3。

```json
{"action":"reply","speech":[
  {"id":"s1","text":"你回来啦。","motion":{"group":"LuluWolf","index":28},"transition":"blend"},
  {"id":"s2","text":"我还在听呢。","motion":{"group":"LuluWolf","index":28},"transition":"continue"},
  {"id":"s3","text":"不过你猜我刚才发现了什么？","motion":{"group":"LuluWolf","index":16},"transition":"blend"}
]}
```

- `speech` 是唯一台词来源，不再同时输出重复 `text/bubbles`。`Live2DDialoguePlan` 拼接文字供现有口语边界/关系检查，同时把原片段保留在现有临时 `Live2DVisualActionBus.Cue`。每个 id 唯一，text 非空，真实 group/index 必须属于当前人物所选模型。仍受原单轮16拍协议约束，不静默截断超额计划。
- 最终口语通过后，动作契约验证整份计划。有效输出零新增模型调用；真实缺失/无效字段最多同一人物同一模型一次元数据补正，不改台词、不重复工具/日程/心理状态。补正仍失败时保留语音并在现有状态中显示原因；改写后的口语不得复用旧计划。正常回复和工具结果回复共用这条视觉发布入口。
- `LuluVoiceCallSession` 仅在整份文字精确一致时直接使用原 `speechParts` 入语音队列；这是完整性比较，不是原文搜索。片段 id/index 与同一 visualSequence 进入 `Live2DSpeechTimeline`，WebView 只播放同一实际发声片段的 beat。旧输出仍按原锚点路径绑定，静默动作仍可立即执行。
- ElevenLabs/MiniMax 的 `CallAudioPlaybackClock` 从 AudioTrack **已消费帧**报告首次声音及实际进度：20ms观察粒度，进度最多10Hz跨桥；不把 HTTP 返回/写入缓冲当成已听见。系统缓存语音由 MediaPlayer.currentPosition 报告。无可测播放位置的兼容通道仍只有真实开始/结束事实，不伪造词级时间戳。
- JS 版本化片段拒绝旧角色/旧会话/旧片段的进度；收到实际位置后，未来节拍仅按这个位置触发，音频欠载时不按墙钟抢跑。原生 motion 的曲线仍由 Cubism 播放，不宣称拥有词级同步或逐采样重定时。
- `continue` 在同一个真实动作仍被持有时不从头播放，不重复切换同名表情；`blend` 强制启动新选中的 motion，但仅对该文件实际控制的参数，从上一帧真实姿态淡入。淡入时间取 model3 条目或 Motion3 Meta/顶层声明；无有效元数据就依赖播放器原有淡入，不编造动作曲线。
- 对于**一段语音明显长于单个 Motion3** 的情况，角色可以在原本的 `speech[i]` 中选填 `followUps:[{"motion":{"group":"真实组名","index":0},"transition":"blend"}]`，最多五个后续真实文件。它们不是音频字词时间戳，也不要求把自然语句按逗号切碎：只有前一个 Cubism 动作实际结束且同一发声片段仍在播放时才顺次启动；片段结束、中断、隐藏、换模型或新决定立即废弃剩余动作。角色自行选择顺序，执行器不能随机编表情或另行付费决策。
- 同一视频电话后续某轮**动作计划未成功**时，仍为真实语音分配新的 `visualSequence`（不含动作的控制标记），替换旧视觉计划并让播放器接受新 TTS 的 `onStarted/onEnded`，不能继续传默认 0 让旧计划的事件序号护栏误拒绝后来的发声。该标记不是动作成功回执；界面显示本轮未能生成/送达 Motion3 的原因，不能伪称身体动了。触摸、特殊眼型、PCM口型仍在后续独立层处理，不被跨动作淡入覆盖。
- 当前 `continue` 不是任意关键帧冻结/循环：动作已结束时可能重新启动，原资源的回正尾段仍保留。长时靠近/定姿需要明确的可保持资源或后续关键帧协议；不能把这一限制宣称已解决。隐藏/中断/换模型取消旧计划与过渡。

本地 JS 验证覆盖相同台词不同编号、跨片段继续/切换、旧时钟拒绝、欠载不抢跑、动作淡入参数掩码及取消，保留原触摸189组合和物理回归。JVM 新增模型目录→分段计划→同源 Cue→实际语音事件的接线回归。Android JVM/APK 与真机的延迟、音色分段连续性、动作视觉质量必须分层核验；本说明本身不是通过证明。

## 历史兼容：语义参数意图与真实执行

```json
{"action":"reply","text":"角色自己要说的话","live2d":{"performance":{"feeling":"thinking","movement":"glance","intensity":0.35,"side":"left"}}}
```

`feeling`、`movement` 可以独立选择，`intensity` 为 0～1（默认 0.45），`side` 为 left/right。角色也可省略 live2d；选择 silent 时仍可立即执行自主视觉回应。它们是当次表演意图，不是新的持久情绪数值。

| 可选神态 | 参数组合方向 |
|---|---|
| calm 平静 | 正常眼睑、回视、收住嘴角和笑眼 |
| smile 浅笑 | 轻微嘴角与笑眼，带轻量头身变化 |
| happy 开心 | 明显笑容、温和笑眼、轻抬头与上身前倾 |
| playful 俏皮 | 嘴角上扬、抬眉、侧目及灵活侧头 |
| affectionate 柔情 | 柔和笑眼、嘴角、向镜头轻歪头与身体前倾 |
| relieved 释然 | 轻松微笑、柔和眼睑与放松体态 |
| amused 笑意明显 | 更明显的嘴角、笑眼、轻眯眼和轻微头身变化 |
| curious 好奇 | 眉毛抬起、视线与小幅歪头 |
| thinking 思考 | 视线短暂侧移、微垂眼与低头 |
| shy 羞赧 | 短暂避视、较轻嘴角、头身稍侧转 |
| sad 失落 | 嘴角、眉形、垂眸与低头 |
| aggrieved 委屈 | 眉头上扬、轻嘟嘴、眼神低垂、歪头与后缩 |
| tearful 含泪 | 委屈眉眼、更明显抿嘴/嘟嘴、低头与上身收缩；有实际流泪 exp3 时一起播放 |
| worried 担忧 | 眉峰上抬、眼神轻低垂及缩肩/低头近似动作 |
| concerned 关切 | 眉眼与轻微低头，保持认真嘴角 |
| serious 认真 | 收住笑眼、轻压眉眼，不额外派发动作 |
| surprised 惊讶 | 抬眉与头身轻微后收 |
| displeased 不悦 | 嘴角、眉眼与克制的头身转动 |

| 可选小动作 | 变化 |
|---|---|
| nod / shake | 单次小幅点头 / 摇头，含回落 |
| tilt | 轻歪头，躯干少量跟随 |
| glance / look_down | 短暂侧看 / 垂眸，随后回视 |
| turn | 头和身体小幅侧转 |
| lean / withdraw | 躯干轻倾 / 稍收回，伴随少量头部变化 |

组合编译为六拍：0、240、680、2000、4500、9000 毫秒。起势与动作峰值在前，后续保持已选面部情绪，身体动作逐渐收敛；最后一拍的保持时间覆盖较长语音。角色讲话时身体还有与真实说话状态相联系的轻微自然动作，未被模型选定的情绪不由系统胡猜。强度改变幅度，方向由角色明确选择，不按回合随机切换。能力上下文只列当前真实骨骼能执行的选项；每拍还会经过原 `Live2DVisualActionBus` 的实际参数校验，不存在的通道跳过。它不制造独立手臂/喉部骨骼，也不切换兽耳、耳机等外观。

强表情仍需本人明确选择真实 `expression` 文件；轻笑、羞赧不会自动升级为星星眼或爱心眼。原 expression/motion/head/body/face/beats 协议继续有效：显式数值覆盖生成值，显式 beats 优先。`durationMs` 可选，控制本拍参数保持时间；到期由原弹簧与面部插值释放到模型姿态。

## 播放与分层

- 一次决定通过 `perform` 原子提交；表情、头身参数、节拍和预制动作一起等待真实 TTS 开始。下一决定会取消旧的未播节拍；静默回应可立即执行。
- 普通完成保留最多 900ms 的当前姿态收敛；中断、隐藏或关闭清理。短句不再在第一帧语音结束时立刻切掉整个神态。失败的 TTS 不会在下一轮补播旧动作。
- 播放状态只驱动真实口型与中性说话微动作，不自动制造微笑。角色本轮选了笑意时保持嘴角与笑眼，`ParamMouthOpenY` 的 PCM 口型独立工作；吐舌继续等真实 PCM 停顿或结束。
- 已选真实动作文件拥有其头、身体、视线通道；有显式参数意图时才覆盖。特殊眼型保留自身眼睑，不被同时选择的笑眼盖住。
- 触摸累积与反射继续走原独立触摸层，角色明确选择的表达优先；不把抚摸计时变成额外付费聊天轮次。

## 验证边界

原生单测覆盖语义编译、强度、方向、未选择/无效意图、显式兼容以及实际骨骼过滤。JS 测试执行真实 stage 入口和最终参数帧，覆盖等待语音、静默执行、中断取消、旧节拍替换、保持时间、特殊眼型、认真说话不自动笑、预制动作的通道归属；原触摸 189 种组合回归保留。真实模型的视觉幅度与角色模型自主选择频率仍需 APK 真机通话观察，逻辑测试和构建不能替代这项验收。
