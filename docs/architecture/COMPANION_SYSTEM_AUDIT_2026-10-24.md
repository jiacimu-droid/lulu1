# 人物系统协同与居民生活检查（2026-10-24）

范围：现行 main 的在线私聊、前台/电话表达适配器、共享人物上下文、心理/关系、记忆召回、居民作息与通信。依据 AGENTS.md、UNIFIED_CHARACTER_CONTRACT.md 与 COMPANION_GROWTH_FRAMEWORK.md。源码检查不能证明所有运行场景或长期稳定性。

## 已定位并修复的公共链路缺陷

| 根因 | 原行为与影响 | 修复所在 |
|---|---|---|
| 模型响应把 reasoning/analysis/thinking 作为空正文的后备 | JSON、流式及意外 SSE 三条路径都可能把内部分析当成聊天正文或行动协议 | CompanionModelGateway、ModelResponsePayload：只接受实际正文；无正文保留失败，不发送分析，也不添加补救付费请求 |
| 私信不在新感知来源集合中 | 收到信虽然能出现在背景材料，情绪更新与关系判断却缺少这条实际输入及通信对象 | CharacterPerceptionContext：接入真实收信证据与对方 ID；离线超过 24 小时仍未处理的来信保留机会 |
| 在外围流程返回时确认收信 | 决策被新消息、通话或在线状态变化中止，也可能推进邮件游标 | ProactivePerceptionRuntime：只在本轮完成实际决策后确认本轮提供的信；思考期间新来的信不被一起消费 |
| 邮箱绕过原始来源撤回 | 删除/编辑接收者时间线后，旧信仍可经邮箱重新进入感知与召回 | ResidentSocialMailbox：读取邮箱、待处理信与历史联系人时核对本人的有效原始回执；对方独立保存的副本保留 |
| 关系识别只认群聊和结束的见面 | 已通过真实私信交流的人仍可能显示“尚未认识” | CharacterSocialRelationship：真实私信也属于相识证据，不据此推断好友、恋人或互相喜欢；关系图随时间线变化刷新并去除重复居民节点 |
| 每日居民决策误用 PersonaAndScenario | 原世界身份被排除；前一日心情、持续念头及普通本地记忆没有统一交接 | ResidentDailyDecision：改用 CharacterAndScenario，复用 CharacterRuntime 的本人状态和本地证据召回；不新增 embedding、rerank 或心理模型请求 |
| 居民计划另存 thought，社交效果旁路执行 | 想法留在计划 JSON，后续心理难承接；发帖/发信的失败可能被吞掉 | 每日想法进入现有心声/因果记录；关系变化指向实际提供的通信/见面证据；发帖和发信经 ToolRouter 分别保存幂等 ID 与独立回执 |
| 每日 Worker 依赖 Activity 已初始化 | 冷启动时模型和仓库未恢复，可能把全部居民都跳过；单人持久化异常会中断余下居民 | tick 开始调用现有后台初始化；逐人隔离普通错误，取消仍向上传递，不自动追加付费重试 |
| 晚间计划文案直接进入实际活动栏 | 只完成位置/时段切换，也可能让“想读完书、想聊天”看起来已经发生 | ResidentDailyRoutine：已确认的日程切换与尚待执行的具体意图分开留痕，计划不制造已读/已聊事实 |

兼容：不覆盖已编辑的人设、关系约定或旧记忆；保留现有计划、邮箱和时间线数据格式。旧模型响应若只有分析而没有正文，现在会明确失败；这是输出边界修复，不再把它当成角色发言。居民同一轮规划会携带更完整的本人状态与相关证据，输入 Token 可能增加，但没有新增独立心理、embedding 或 rerank 请求。

## 协同链路的检查结论

- 常用在线私聊实际由 ProactivePerceptionRuntime 决策，不是旧聊天页的 sendAndReceive。它已有同次理解、心理、选择与执行；本轮修的是邮件输入/确认断点，没有另造心理循环。
- CharacterRuntime 和 UnifiedMemoryOrchestrator 已统一处理角色资料、核心记忆、有效来源、相关原始证据、学习理解与持续状态。前台表达仅落实既有意图；真实人物场景使用 CharacterAndScenario 时需要由调用方明确交接适用状态，不能只看名称就认定它自动带齐全部记忆。
- 心念、发送和执行是不同事实。ToolRouter 保留各自回执，UnifiedReplyAndActionPolicy 区分实际送达、明确沉默与失败；本轮沿用这些边界，不增加通用道歉/安慰模板或统一性格。
- 原始事件删除已有心理、成长、学习、记忆失效联动；本轮补上了此前遗漏的邮箱召回入口。并发源撤回、跨多条事件的完整因果依赖仍值得继续专项验证，不能宣称已穷尽。

## 居民目前能怎样生活

已有免费本地作息：工作、错峰午休、下班和回家休息；位置、身体状态、咖啡角点单/实际食用通过已有世界执行器保存。仅执行应用实际观察到的时间段，不补造未运行期间发生过的聊天和吃饭。

在设置中明确选择“居民每日规划”模型后，每人每天最多一次实际规划请求，自选午休、晚间地点和活动，也可发信、发动态或保持独处。公共地点的真实同场、共同群聊、见面或有效通信提供联系人资格；每个人的主观看法归其自己的心理 Store，不共享好感分。没有选择该模型时，固定职责仍运行，自主规划不会静默改用聊天模型计费。

本轮接通：自己的实际生活/来信 → 本人旧状态与记忆 → 当天选择 → 真实发信/动态回执 → 后续本人的关系与记忆。它能支持基础生活与慢速通信，但还不是随时发生的丰富居民社会模拟。

## 仍需后续处理，未在本轮冒充完成

1. **消息长期归档（较高优先级）**：ResidentSocialMailbox 仍将全局工作集截到最近 1200 条。双方原始时间线保留原文，但邮箱视图、联系人和游标缺少基于原始档案的完整分页恢复。应将现有邮箱改为可分页、可索引且纳入备份/撤回的长期存档；不能只删除上限后把多年消息全部加载到 RAM。
2. **居民回应及时性与总费用（中优先级）**：普通居民的自动思考默认关闭，独立每日规划仍只有一天一次，刚错过当天规划的来信可能等到次日。可在同一人物循环上加入“真实来信/真实碰面触发”的有限机会，并与主人配置的居民总调用预算共用额度；不自动建立无限互回或额外收费轮询。现有 MomentsStore 会让其他在线主角独立判断是否回应居民动态，这些是另外的模型请求，当前不属于该居民的每日规划额度；“每人每天一次规划”不能解释成整个数字世界只收费这些次数。后续应将社交反应也纳入可见的预算与诊断。
3. **作息的选择空间（中优先级）**：当前可自由选择的主要是午休和晚间；店员班次较固定，工作时段动作以职责切换为主。可复用个人日程安排具体工作、爱好、约见和休息，保存目标/地点/时间及独立回执；先有实际邀请，再由收件人自己决定是否接受。
4. **失败与恢复（中优先级）**：每日请求在联网前持久占用当天尝试，超时/无效 JSON 后当天不自动重试；避免重复收费，但居民可能整天没有新计划。后续应区分“已保存决策待执行”与“模型生成失败”，给出可恢复执行和由主人控制的重试机会，仍保留每次费用痕迹。
5. **长期容量与真实自然度**：若干本地 Store 和世界事件仍整体 JSON 读写/聚合；需按实际数据量测量并分批改为分页/索引。源码与固定 mock 不能证明模型会自然接话、长期关系会成长或 Android 锁屏多日运行可靠。

最后移除“没有本人计划也生成默认私人愿望”的作息兜底后，另行复跑居民日常与规划的 6 项测试，全部通过。

验证期间修正最新 main 中三处既有 JUnit 断言参数顺序错误，并给两份既有集成测试补齐 WorkManager/角色状态初始化。居民模型次数测试将其他在线角色独立的朋友圈反应隔离，不把别人的决策计作本人重复规划；没有删除或弱化原断言。

APK 构建、手机安装、多日运行与真实模型的自然表达尚未验收；上述单测不能代替这些结果。
