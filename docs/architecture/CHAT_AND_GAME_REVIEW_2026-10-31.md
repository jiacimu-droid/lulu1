# 聊天与游戏整体检查 · 2026-10-31

范围：当前 main 的源码链路。未读取手机上的实时人设、真实请求输入或实机帧，不把源码判断冒充模型效果验收。

## 整体结论

统一人物事实、身份和模型网关仍在；目前的主要问题是入口的编排差异、表达指导的默认节奏不明确，以及游戏将关键操作信息放进管理面板。无需新造人格或推翻原有因果循环。

## 聊天与对话示例

- `ProactivePerceptionRuntime` 的在线未读私聊通过 `privateConversationInstruction` / `proactiveDecisionInstruction(directPrivateChat=true)`，一次决定直接发出台词。
- `LuluDeviceToolBridge.respond` 的前台私聊仍有 speechIntent/dialogueMove → 表达的分阶段交接；电话、群聊有各自的媒介结构。共享网关 `CompanionModelGateway` 读取 `CharacterRuntime.definition`、`CharacterExpressionGuide` 与 `CharacterSpeechIdentity`。因此“统一人物”已存在，但“所有入口完全同一编排”并未实现，修改某一入口不保证其余入口同等表现。
- 角色个人 `profile.dialogueExamples` 已接通，且从普通人物背景投影排除，不作为实际历史；修改它会使实时配置快照失效。无需再叠加一套对话示例 Store。
- 原指导允许说到位后停，也同等强调随兴展开；没有把日常的轮流接话明确为默认。分泡仅处理呈现，不能减少模型一次选择的内容。此次在现有共享私聊/表达指导中明确：学每一拍的接话与交还话轮，示例下一条用户原话尚未发生；多个气泡合计仍是一轮。认真分析、创作等仍保留完整表达能力，无输出剪裁或新增模型调用。
- `CharacterSpeechIdentity` 原先直接 `take(1100)` 可能切断用户编辑的长示例、最后的用户接话或角色回应；此次完整保留个人示例。该缺陷不证明用户手机的示例已经被切断，也不能单独解释全部长回复。
- 尚待真实质量验收：同一人物分别经在线私聊和前台交接，测试随口招呼、玩笑、倾诉、详细分析和工具后回复；记录实际输入、输出及入口。文本契约测试只证明组装内容，不能证明模型已学会自然接话。

## 游戏

当前 `LuluGamesApp` 有统一游戏路由与沉浸框架；探索游戏仍分别拥有规则、存档和伙伴执行器，不能以一个框架已修改推断所有游戏都改善。

本次优先检查用户描述最接近的“迷雾摸金”（`RelicEscapeScreen`）：

1. 镜头在地图边缘钳制，开局 (2,2) 的人物会靠近左上 HUD；小人没有身份文字，玩家、伙伴和地物难辨。此次共享绘制/触摸镜头变换、允许边界外留空以居中人物，并标记“你”、实际伙伴名、撤离门。
2. 伙伴可能在视野之外，原来没有直接定位。新增“定位你/找某伙伴”，仅改变镜头和选中目标，不移动人物、不耗回合、不调用模型；玩家移动后镜头回到本人。单人局明确显示“本局单人探索”。
3. 指引、目标、主按钮提示多在 `tools` 面板，正式画面只露出按钮，学习成本高。此次将最少的移动/选目标提示、当前主操作提示与找宝箱→绿门撤离目标放进常驻操作区。
4. 伙伴是真实独立棋子。`RelicActorPlay` 提供合法行动，由角色模型选择，经 ledger 写入；不是画面摆件。但每局每人每回合最多一个行动，模型结果可能落后于玩家连续移动，体验上不保证实时并肩。此处没有擅自增加自动跟随、额外付费心跳或改变回合规则。
5. 撤离只带走出口附近、活着的伙伴及其物品（`RelicEscapeRules.success`）。下一阶段应重点做全队距离/撤离准备的可视反馈，以及快进操作时的伙伴节奏验收。不能靠旁白说“在你身边”掩盖实际坐标，也不能偷偷替角色移动。

方块小岛保留独立 `BlockIslandRules`、真实队友与存档，深海等游戏各有入口；本轮未完成这些游戏的全面可玩性、全流程与真机触控验收，不宣称游戏馆整体重做完毕。
