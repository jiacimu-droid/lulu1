# Live2D 触摸反应设计与实现 · 2026-10-23

本次根据主人提供的 `live2d.zip` 文本资源设计；不向仓库提交模型、贴图或专有 Core。只修改本地触摸表现与真实触摸回执，不改任何角色的人格、统一认知链或台词。

## 模型实际能力

- `小狼.model3.json` 原文件没有 Motions 和 Expressions 列表。已有导入适配器会注册同目录的九个真实 exp3。
- CDI3 共 143 个参数。眉眼、眼球、嘴形、鼓脸、嘟嘴、头部九轴、身体旋转及兽耳物理参数可用于组合动作。
- 可用表情：脸红 `bq4`、流泪 `bq3`、脸黑 `bq14`、爱心眼 `bq6`、星星眼 `bq19`、吐舌 `ParamTongueOut`。
- 兽耳、耳机、麦是外观开关，触摸不会自动切换。自动触摸不选吐舌；手动和角色主动选择的表情继续走原语音同步门控。
- 没有独立喉结、肩部或手臂动作参数，不声称能抬手或吞咽。相关区域由真实可用的头颈、视线与上身动作近似；兽耳仅在实际 Core 存在对应参数时驱动。

## 21 个接触区

左兽耳、右兽耳、左人耳、右人耳、头发、额头、左眼、右眼、鼻子、左脸颊、右脸颊、嘴巴、脖子、喉结、锁骨、胸口、左手臂、右手臂、左手、右手、身体。

左右沿用已有画面坐标约定（画面左/右），各自独立校准；左右动作镜像。旧 `ear-left/right` 校准中心和尺寸保留，不猜测迁移其位置，新兽耳与喉结使用独立键。旧 `head/arm` 事实标签仍可读取。

## 接触矩阵

| 区域 | 手掌抚摸 | 嘴唇亲吻 | 手掌扇击 |
|---|---|---|---|
| 头发 | 睁眼注视 / 眨眼微笑 / 放松眼睑、微仰头 | 闭眼、轻低头 | 先缩头，再皱眉鼓嘴 |
| 额头 | 仰头、眉眼放松 | 闭眼、轻偏头 | 缩头、皱眉 |
| 左右兽耳 | 单侧轻颤、侧倾 | 单侧耳朵收动、低头 | 单侧耳朵回弹、缩头，再委屈 |
| 左右人耳 | 缩颈、偏头、轻微害羞 | 更明显缩颈、侧目 | 头随受力方向偏开，再皱眉 |
| 左右眼 | 被碰的一侧合眼，另一眼保留 | 单侧轻闭、眉眼放软 | 先闭眼闪躲，再单侧眯眼、委屈 |
| 鼻子 | 缩头、眨眼、轻抬眉 | 微仰头、短暂眯眼 | 后缩、皱眉 |
| 左右脸颊 | 向手心靠、视线侧移、眉眼微笑或害羞 | 先短暂睁眼，再侧目低头 | 先受力歪头（颈部侧倾为主、转脸为辅），再委屈抿嘴、皱眉或含泪 |
| 嘴巴 | 抿嘴、轻嘟嘴、视线向下 | 先怔一下，再闭眼、低头、嘟嘴 | 收嘴、偏头，随后委屈 |
| 脖子 | 缩颈、侧倾 | 缩颈更明显，侧目、害羞 | 缩颈、躲开、皱眉 |
| 喉结 | 轻抬下巴后回收 | 先抬下巴，再低头躲闪 | 下巴回收、皱眉 |
| 锁骨 | 肩颈效果由头身微缩近似，低头看 | 低头、身体微收，害羞较强 | 上身缩一下，再皱眉 |
| 胸口 | 看接触处、身体轻晃 | 低头、身体微收 | 上身向后晃，再抬眼 |
| 左右手臂 | 看向被摸侧、身体微侧 | 看接触处、抿嘴微笑 | 同侧身体轻缩，再委屈 |
| 左右手 | 看向手、身体微倾 | 看接触处、微笑 | 同侧身体回缩 |
| 身体 | 上身微动、轻微放松 | 上身微收、柔和眉眼 | 上身按方向缩动 |

所有组合支持轻 / 中 / 重。手掌「扇」仍使用兼容旧记录的内部 `slap` 手势码，UI 和新事实描述均为扇击。左右拖动确定扇击方向；轻中重改变冲击幅度。脸颊扇击以颈部侧倾 `ParamAngleZ` 为主要运动，`ParamAngleX` 仅少量配合，身体随动；本轮提升脸颊扇击的颈部 Roll 和上身跟随幅度，未指定左右方向的单次「扇」默认向画面左侧明显偏头，横向拖动则依真实方向偏头。头发、鼻子、胸口等仍遵守各自受力部位。受力峰值持续约 230ms，冲击弹簧快速起效并较慢回弹，随后由短暂睁眼惊讶转为眉头上扬、眼神下移、委屈嘟嘴；有真实流泪 exp3 时渐渐出现泪眼。按住尚未松手时不预先触发扇击。

遵从主人后续修订：脚踢入口、执行、动态反应和新增回执均移除；旧踢的历史描述仍可读取。拍击点按不再误作普通轻点，亲吻拖动不混入抚摸。

## 渐进表现

这是单个已加载视频舞台的短时**视觉响应值**，不是另建人物心理或关系库，不作为人物已害羞、爱上或同意的事实。正式人物理解继续使用同一真实时间线与模型。重载舞台从自然状态开始，暂停恢复保留原值并按真实经过时间衰减。

- 按住期间即时变化：静止接触按时长缓慢增加；连续左右滑动按真实时长及实际路径距离增加，不等待松手。长抚摸到达表情阶段时，手尚未松开就会逐渐脸红。
- 不是每个 MOVE 都加一个完整触摸。时间贡献按指数衰减的解析积分计算、距离贡献按路径累计；同一路径和时长在 15Hz 与 120Hz 下结果一致。停止滑动后回到较慢的按住速率，移出模型、取消、切换/隐藏舞台停止后续累积，校准不累加。
- 松手只结束本段接触并提交一次原时间线记录，不再把已经随时间积累的抚摸重复加一遍；亲吻与手打仍按一次实际完成动作计算。快速轻点保留一次很小的响应。
- 同一部位族共享贡献，左右切换和改变抚摸方向不能绕过该部位的低敏感上限；头发反复抚摸最多贡献 8/100，额头 10/100。
- 中等力度连续滑动的基础时长增速：摸脸约每秒 2.2、摸嘴约每秒 4.4，另加实际路径贡献；静止按住速度更慢。离散亲吻的增量：亲脸约 15，亲脖子约 32，亲嘴约 56，亲喉结/锁骨约 50。不同部位可逐步叠加，总显示量不超过 100。
- 14 起允许淡脸红，强度随当前值变化，并有淡入淡出；低于此值不为“必须有反应”乱选爱心眼。
- 86 起且本次确实亲嘴、脖子、喉结或锁骨，才允许真实爱心眼；60 起且本次逗鼻子或兽耳才允许星星眼。摸头自身不能刷到这些条件。
- 视觉亲昵贡献按 45 秒半衰期自然回落。扇击仅累积独立受力值 `impact`，不会增加亲昵害羞值，并会弱化已累计的抚摸反应；立即清掉旧爱心眼。受力表情优先惊讶 / 委屈流泪；**自动扇击不再选黑脸**，即使多次高力度命中。没有流泪资源时只执行参数眉眼和受力动作，不用黑脸伪装哭哭。
- 自动叠层只用导入文件里真实的 Add 参数，并检查 Core 的实际 ID 和上下界。不存在参数跳过；不靠文件名凭空制造效果。角色或手动选择的明确完整表情保留原资源优先权；局部触摸即时眉眼、身体反射在短时接触期间优先于普通聊天编排，接触后由原平滑弹簧复位。

以上数值是本次用户明确要求的局部动画调参，不是 API、数据留存、人物行为或长期能力限制。

## 本轮画面与头部运动调整

- 闲置时不再给头部施加持续左右摇脸的 Yaw，保留较小的颈部 Roll 及独立呼吸；角色本人主动选择的摇头、转身、说话动作不受此闲置规则限制。
- 抚摸脸颊、头发、耳朵等以接触部位、左右和真实羞涩累计值为依据，呈现不同睁眼、害羞半垂眼、眉眼与笑意，而非每次都眯眼。亲吻仍在适合部位提供更高的羞涩增量。
- Android 二进制 JPEG 原生画面依实际解码 ACK 调整 Pixi 30/36/45 FPS 上限；通过当前收到帧的 FPS、p95 间隔调节画质传输分辨率。流畅模式由 860px 提高至 980px 起点，低画质下限从 650px 提至 800px；高清传输上限限制 1600px，避免极高分辨率读回拖慢画面。旧安卓回退通路仍保留，但其帧率不等同于 GPU 渲染 FPS。所有帧率和画质表现均需实际手机验收。

## 校准与数据

- 最小横向半径从模型宽度的 3.5% 改为 0.3%；鼻子初始 1.4%、嘴巴 2.5%、喉结 1.8%，每区有适合的小尺寸。
- 圆的纵向半径按模型宽高比换算，移除原来的纵向最小值；长模型不再把鼻子圈撑成覆盖整脸的椭圆。
- 细轮廓、极淡选中填充；21 区都画出。滑条即时改变选中圈和真实命中边界，保留中心并保存，重启恢复。
- 缩小后的区替代该区原来的粗略命中；小区和大区重叠时优先小区。其他区及原数据保持，校准存储继续按模型 URL 保存，沿用 v1 SharedPreferences。
- 原调用、会话 ID、真实画面校验和触摸聚合保持。每次完成接触的部位、接触工具、方向、力度进入原时间线；回执包含整次手势总时长（不是在最终部位的精确停留时长）。不逐采样落盘或把视觉响应值当作真实人物心情，不新增模型调用。

## 验证与边界

现有发布工作流运行 `touch-hit.mjs`、`parameters.mjs`，打包 renderer，执行 Android 单测与 assemblePhone。扩展回归覆盖 189 个部位/工具/力度组合、小圈持久化、重叠边界、渐进与衰减、受力阶段、单侧眼、实际 Add 通道释放及工具点按识别；还执行真实舞台入口，验证长抚摸未松手即增长/变红、采样率一致、松手不重复加点、移开停止。

JavaScript 测试、bundle 构建、Android CI 和真机分别报告。骨骼正负方向、兽耳物理幅度及手机实际观感仍需此模型真机验收，不能用这些检查冒充实际看到的动作效果。
