## 三、记忆专项剩余范围

此节补充看板的技术边界，不另列一套进度。

- **M1 → P-05**：验证现有精确原文分段的首/中/尾限定、源版本、预算缺段和实际注入。按需范围展开是否仍缺能力需沿正式调用点证实，不能重新实现已有分段，也不能将任意长正文整段塞入每轮提示词。
- **M2 → P-06**：核查原请求是否完整承接明确 timeRange、世界/地点稳定 ID、participantIds、episodeId、taskId 与依据。模型负责自然语言指代，程序执行已明确的结构条件和可见性；同名地点不合并，电话/私聊不补造坐标。
- **M3 → P-06**：沿原 taskId/sessionId/事件修订展开“起因/目标 → 本人选择 → 实际动作 → 独立结果 → 后来改变”。时间相邻或话题相似不能直接证明因果；摘要必须能指回原文。
- **M4 → P-09**：测量向量缓存淘汰/重建、召回全量扫描和对话锚点分页成本。依据数据决定是否在现有权威上增加可重建索引或分页；R-tree 只在真实坐标半径检索确有需求时评估。
- **M5 → P-07**：核对旧摘要、主观认识、用户事实及当前情绪的有效期/替代关系，同名人物不自动合并。归档保留原文、证据及合法恢复/撤回路径。
- **M6 → P-07/P-08e**：候选召回、实际注入、最终判断与手机实际行为分层核对，纳入编辑删除、断网、强杀重启和跨角色隔离。

既有权威与实现入口：SharedExperienceTimeline、UnifiedMemoryOrchestrator、MemoryWorkingSet/Policy、OriginalEvidenceSpans、MemoryInspectionStore、MemoryValidityStore、MemoryEmbeddingIndex/Lifecycle、NarrativeEvidenceChain。外部 eMEM 的联合时空查询与经历组织仅作为参考，不代表客户端已接入 eMEM/hnswlib/R-tree，不直接迁移其原文清除策略。

## 四、人物与社交的真实验收样本

优先采用获授权的脱敏真实回合，覆盖：普通玩笑/分歧、疲劳与学习压力但未请求方案、明确详细求助、用户纠正、条件改变、工具失败、持续约定跨日、角色分享/邀请、放下与重新考虑私人愿望。

同一人切私聊、电话、群聊、后台、日程、游戏和视频，核对完整输入、配置与模型连接、所选意图、真实工具参数、逐步结果和下一轮。额外使用主动/克制等对照人设；不把所有角色统一为热情、温柔或责任型。用户原话、角色原话、听见别人的话、私人心理和未证实状态严格区分。

社交另验：双方独立收发与想法、关系方向不对称、真实共同话题、邀约接受/拒绝/另约、到场/失败和各自后续。不能用每日固定发帖数或互相唤醒制造热闹。居民地点分布按实际日程和身份职责判断，不能硬编码搬家。
