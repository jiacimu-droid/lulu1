## 二、第一优先：人物活人感与完整因果

### 1. 保住本人、现场与完整含义

- 审查私聊、后台感知、电话/视频、群聊、日程、工具反馈和游戏的真实网关输入。确认同一份稳定人格、对象关系、相关经历和当前目标确实参与判断，隔离世界按既有边界排除原世界关系。
- 保留原话与模型已经作出的完整立场、否定、条件、时间范围和不确定性。持久化不是显示预览；上下文预算由既有工作集选择完整证据，不能先把权威含义截坏再召回。
- 排查陈旧心理被当成当前原则、通用助手口吻或“怕打扰”覆盖本人、表达模型重新决定行动、执行器按次数/关键词替角色改变选择。
- 同一事件的见证者不等于作者，群聊尤其如此。本人发言锚点、个人表达参考和行动证明必须共用原消息的稳定作者 ID，不能依赖昵称或事件所属角色。当前轮次以此为已证实根因推进；详细验证状态记入人物进度。

### 2. 让取舍、执行与后续真正接上

- 逐项追踪原 motive/concern/experience/task ID：当轮选择 → 多动作执行 → 每步成功/失败/待许可/未证实 → 下一轮同一角色。不能把工具请求、通知送达或角色自述当成目标已经达成。
- 后续时机由本人在原有决策中选择，复用现有日程/唤醒计划。不新增固定催促、按关键词触发的剧情、每几分钟强制关心或常驻付费反思。
- 用户说暂时忙、拒绝、改变条件或未回复后，下一轮带回真实观察与未知项，由本人决定继续、改法、等待或放下。不能静默丢失挂心，也不能程序替他执着到底。
- 除表达质量外，检查体验上的“正在处理/等待真实结果”反馈。运行失败要如实记录，不能展示成角色已经主动放弃、完成或满意。

### 3. 验收按完整场景，而非漂亮台词

使用主动/克制等不同人设，覆盖同一场景的不同有效选择、多轮纠正、否定条件、切场景、拒绝与恢复、工具失败、晚到回执、重启与来源撤回。固定假模型只验证契约与执行分支；真实模型是否自然、是否像本人，必须另列真实运行证据。

### 4. 活人感专项：从真实互动的因果与话轮找根因（P-08 的执行路线）

**观察与判断边界。** 主人 2026-11-03 的私聊截图中，江渡面对头晕、学习压力和“剩 40 多天”，连续多泡复述压力、解释心态、给学习安排，读起来像已写好的劝导稿。这证明一次可见回复不自然；单张截图没有该次模型配置、完整用户原话、决策 JSON、表达 JSON 和真实发送/后续记录，**不能断定是人设差、模型差或某一条提示词独自造成**。现有源码已经有 `CharacterInnerLifeStore` 动机、`ConversationDominantImpulse`、`DialogueMoveEngine`、`CharacterExpressionGuide`，前台私聊在 `LuluDeviceToolBridge` 分别产生 `speechIntent/dialogueMove` 与最终 `bubbles`，在线私聊走 `ProactivePerceptionRuntime` 的直接决策，`QqChatReplyEngine` 才实际发送。`ConversationNaturalnessGate` 有词形评分和局部重写入口，前台表达当前不让词形分数自动替换已选台词。以前的提示词改动只证明契约组装，**没有真实模型质量证据**；继续追加“自然一点”没有诊断价值。

## 三、第二优先：角色自己的社交网络

目标不是后台随机刷对话，而是“共同经历/兴趣 → 选择联系谁 → 对方独立回应 → 双方各自形成印象 → 下一次关系与行动”。复用正式私信邮箱、社交关系图、动态与群聊，不建立第二套人格或关系分数中心。

1. **可靠投递与独立接收**：发送、送达、已处理、回复分别记录；收件人承接自己的身份、关系、记忆、心事和当地现场。不能由发送者同时编造对方回应，不把角色社交内容自动当成已经告诉用户。
2. **有差异的关系**：A 对 B 与 B 对 A 可以不同，亲近、分歧、信任和边界要有来源。相同事件可能有不同感受；不能统一好友度或全员围绕用户说话。
3. **形成可延续的话题**：共同活动、真实见闻、相关兴趣、未尽问题可以成为联系理由；回复能修订原心事或带来新打算。已有联系人候选若总取前几位，需先验证是否实际造成长期饥饿，再修工作集公平性；不强制每日联系数量。
4. **邀请的完整闭环**：本人邀请 → 对方接受/拒绝/另约 → 到时可执行 → 实际到场或失败 → 各自结果。已有群创建、群发言、邮箱与世界事件应联通，而非再造活动聊天室。
5. **给主人可理解的观察入口**：沿现有角色手机、消息和世界展示关系与经历，能追溯谁说了什么；私聊、群聊、转述、个人想法清楚区分。用户代发的内容不冒充角色自主创作。
6. **运行成本**：以真实新邮件、世界事件和既有在线感知触发，优先复用原调度。每一方做决定仍归本人；不能为保持热闹新增无意义常态模型调用或无限互相唤醒。

## 四、单人游戏与双人/多人游戏

### 单人及轻量对局

- 翻牌现有 `ImmersiveMemoryMatchScreen` 的对手会直接从隐藏牌面寻找配对，这是可复查的公平性缺口。后续改为只能使用已经公开的牌和自身实际观察；难度可影响记忆/策略，不能靠假失误掩饰全知。
- 核对骰棋等回合游戏的轮次、合法动作、输赢反馈、重开和存档；深海旅程关注探索方向、选择后果与持续进度。先按实际玩法找阻碍，不以增加文案代替可玩性。
- 游戏里的角色发言需承接当局真实事实和本人。`CharacterAndScenario` 等现有模式是否缺少此场景必要的相关记忆，要逐调用点确认；不直接把全部现实记忆塞进每一个隔离剧情。

### 岛屿共同生活与遗迹合作

- 岛屿沿 `IslandHouseProjects` 等已有能力完成规划、找材料、建造、使用、再次共同回来的一条体验线；检查玩家意图、角色自主行动与共享世界资源是否一致，避免只加任务面板。

- 小剧场阅读：WorldLifeEpisodeReader 对带姓名的对白提取说话者，在浅灰色独立卡片中呈现；旁白和心声使用原各自样式。WorldLifeNarrativeGuide 只倡导分段转述真实证据里的原话，不为了排版编造角色台词。原保存的文学全文不变。
- 回归候选：ResidentDailyPolicyTest、AutonomousEncounterDirectorTest、WorldLifeEpisodeParagraphsTest。更新索引须使用仓库原有 scripts/generate_code_index.py 工作流，不能手动伪造索引。

### 下一阶段最重要的真实验收

1. 新增设置是否在真机正确持久保存并被冷启动 Worker 读取；预算为 0/2/5/8 时分别核对每日新排程数与后续实际工具回执，旧日程不丢。
2. 检查居民各日实际地点分布、时段与身份工作职责；若扎堆仍发生，依据模型选定的午休/晚间地点与定时职责记录判断根因，不用硬编码随机搬家。
3. 用实际原住民邮箱和时间线确认：主动私信请求 → 真实送达 → 对方独立决策 → 真实回应/不回应 → 后续关系变化。已有代码具备通道，但没有真实观察数据就不能宣称社交体验已修好；不要用增设每小时收费轮询制造虚假热闹。

方向仍服从全文总优先级：人物活人感和因果连续性第一，角色社交第二。不是为了人为填充活动次数而强制 NPC 发帖、发消息、打电话或去咖啡馆。

## 2026-11-03 · 记忆系统核查与 eMEM 借鉴路线（检查与规划，未新增实现）

### 结论与原始资料

核查基线：main `9dc4271`。露露机已有长期记忆与统一召回，未在已查正式链路中发现接入 eMEM、hnswlib 或 R-tree 的实现。截图中角色读到论文、在心声中总结架构，不代表客户端已经装上该系统。

参考的 eMEM 是 Automatika Robotics 的具身记忆项目，面向带真实空间观察的代理；其共同图模型组合语义、时间与空间索引，并将观察组织为事件片段与摘要。原始资料：[论文 arXiv:2606.03374](https://arxiv.org/abs/2606.03374)、[作者仓库及 README](https://github.com/automatika-robotics/emem)。同名 emem.dev 等项目不能混用为本次来源。最适合露露机借鉴的是统一查询条件、经历组织与可追溯摘要；是否采用具体依赖必须另做 Android/ARM64、性能、维护与许可评估，本轮没有复制第三方代码。

### 分阶段改进与验收

**M1／第一优先：记忆进入决策时保住完整含义与来源。**

- 已见源码风险：MemoryWorkingSet 对超过 3000 字符的原始事件保留前 2200/后 650 并明确标记中段未注入；这比无标记截断可靠，但关键条件仍可能只在中段。UnifiedMemoryOrchestrator 的紧凑渲染与任务摘要、CharacterContinuityRuntime 的短预览也须沿正式调用点核查，不能仅提高固定长度就算解决。
- 拟改：沿原 eventId/revision 提供有范围、可追溯的原文分段读取，选中关键片段时同时保留其上下文限定。复用既有模型决策/工具能力和工作集，不强制每轮多调用一次模型；不能把不连续首尾当作连续原文，不以摘要替代原始执行证明。
- 验收：否定/条件在首、中、尾；长工具回执、跨轮更正、同名角色/群、来源编辑删除及晚到提取。旧心理与当前状态分开，个人经历与旁人发言分开；原始资料保留、核心记忆及既有删除语义保持。

**M2／第一优先：统一“时间＋地点＋人物＋事件”的查询契约。**

- 已证实的接口缺口：UnifiedMemoryRequest 主要把 currentInput/sceneContext/recentContext/taskIntent/actionContext 拼成文本；MemorySearchQuery 从文字提取时间范围。它不是统一的结构化 timeRange/placeId/participantIds/episodeId 查询契约，MemoryEntry.sceneKey 也不能直接代替地点身份。
- 拟改：在原请求/事件投影上承接明确的时间范围、世界/地点稳定 ID、参与者 ID、来源/任务/事件 ID，以及它们的来源依据；先按本人可见性与真实条件过滤，再联合语义检索、重排和经历展开。自然语言中的“上次在那里”等指代由同一角色模型结合上下文解释；程序只执行已确定条件，检索词规则不成为新的行动/意图解释器。
- 地点优先复用数字世界稳定 location code，并区分世界命名空间和历史位置；电话/私聊不要求伪造坐标。“咖啡馆”同名不等于同一地点，当前所在地不证明过去就在这里。没有真实坐标时保留未知，不读取现实 GPS 来补齐数字世界，不把全局居民登记当作本人见闻。
- 验收：同名不同地点、同一对象跨场景、历史地点更名、不同世界、跨日/时区、未知地点、用户纠正时间，以及其他角色不可见的私信始终不能被召回。

**M3／第一优先：按完整经历承接原目标与真实结果。**

- 拟改前先审查 NarrativeEvidenceChain 的 task/session 邻接与现有 WorldLifeEpisodeStore、DigitalWorldResidentEpisodeStore 等投影：完整经历应能追到“起因/原目标 → 当时本人选择 → 实际动作 → 独立结果 → 后来修订”，包括失败、中断、未证实与明确放下。不要另建人物中心，也不把相邻时间或相同话题自动认作因果。
- 摘要可作为检索入口，必须指回所摘要的原事件及修订；按需展开相关经历，而非只取最近几条或把同场景所有事件绑成一个大团。
- 验收：数日后找回早期约定及其后来修改、工具失败后后续选择、多个并存目标不串线、用户不在场的角色社交不冒充已告诉用户。旧存量成长/摘要的依据是否仍有效也需检查，不凭空重写旧历史。

**M4／性能与费用：先测量，再决定 ANN 和存储调整。**

- 已见源码事实：RelevantMemoryRecall.rankByEmbedding 遍历有效记忆并逐一比较向量；RawTimelineMemoryRecall 与部分经历展开读取本人完整时间线。MemoryEmbeddingIndex 是逐文件向量缓存，最多 2400 文件，超出后按最近访问淘汰缓存；缺失向量在召回侧可按批重新计算。缓存淘汰不等于原始记忆删除，但在规模较大时可能反复重建，实际影响待测。
- 先测不同角色数、1千/1万/10万条记录下的冷/热启动、候选召回率、P50/P95 延迟、RAM、磁盘 I/O、向量缺失/重复计算、实际 API 次数及后台恢复；这些规模是测试档位，不是宣称手机必须承载的保证。
- 基于测量决定是否把摘要/关联索引迁移到已有 SQLite 持久层并分页，或在原向量权威上增加可重建 ANN 索引；小规模保留精确检索作基线与回退。迁移需可恢复、验证来源/修订/删除一致，不能照搬 Python hnswlib 到 Android，也不能以永久删记忆解决缓存压力。
- R-tree 为后置可选：只有真实游戏/世界坐标和半径检索需求、且稳定地点过滤不足时才评估；聊天陪伴优先解决人物、时间、场景和因果关联。

**M5／摘要与实体持续更新：保留原文，处理变化。**

- 复用 MemorySemanticConsolidation、MemoryValidityStore 和 sourceRevisions，核查“当时如此/后来改了/主观印象/待证实”的有效期、替代与反例。人名、昵称相同不自动合并人物；近期情绪不升级为永久人格。
- eMEM README 的归档流程会移除原观察文本和向量、留下摘要；此策略不直接采用到露露机。露露机应保持原文可查、按需归档与恢复，并承接来源撤回及备份迁移。
- 整理复用已有维护节奏和已配置连接；为每条消息额外收费提取、反思、实体识别，不属于本路线默认方案。

**M6／统一验收：召回正确，还要真正到达本人判断。**

- 建立可复查的真实来源测试集：较早但相关的经历、相似话题诱饵、跨地点同名事件、用户明确纠正、长段中部条件、摘要冲突、角色隔离、删除/编辑、断网与强杀重启。
- 同时检查候选召回、事实准确、来源/修订、实际注入、预算遗漏和最终决策引用，沿 MemoryInspectionStore 扩展审计；检索分数高不等于模型确实看见/正确使用，也不等于用户满意。
- 先做确定性的契约/生命周期回归，再单列真实模型的人设一致性、自然使用回忆与多日手机表现。eMEM 的具身测试成绩不转述为露露机的体验成绩。

执行顺序：M1 → M2/M3 → M4 测量后选择实现 → M5/M6 随各阶段贯穿。属于人物活人感第一优先级，不改变“角色社交其次、游戏与视频随后”的总路线。各项均为下一步检查/实现目标，本轮只更新文档，没有更换运行中的记忆引擎。
