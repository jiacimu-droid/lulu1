## 一、产品方向与执行规则

**产品定位**：以数字生命为中心的手机 App。角色跨聊天、电话、Live2D、数字世界、社交、游戏、阅读、手机操作等场景保持同一身份、关系、记忆、主观判断与真实行动回执。目标是**真实可用和自然相处**，而不是功能数量或测试数量。

**发行分支**：
- `main`：默认版，不开放《方块小岛》G-02、《迷雾摸金》G-03；保留已有历史存档。
- `game`：游戏体验版，额外开放 G-02/G-03。通用功能只从 `main` 同步至 `game`，游戏专属改动**绝不回写 main**。
- **新安装空白**：不预装私人伴侣、私人聊天、欢迎词、私有人设；旧安装原本数据必须保留。只允许一名非伴侣的默认咖啡馆居民。

**三条现行自动开发任务**：

| 负责人 | 分支 | 频率 | 主责 |
|---|---|---|---|
| 主线开发与 CI 验收 | `main` | 每小时 | 手机操作、UI/ANR、电话、经典小游戏、数据/记忆/社交、新用户体验、新故障和无人认领的 Issue |
| 人物因果专项 | `main` | 每两小时 | P-08b/P-03 同一人格、关系、心理、记忆、跨入口自主决策和事实回流 |
| 双游戏专项 | `game` | 每小时 | G-02/G-03 玩法、美术、角色协作、真实结算和手机体验 |

**每轮只做五件事**：
1. 刷新**目标分支**最新代码、看板和 Actions；旧提交/旧失败仅作线索，不反复修已解决的问题。
2. 选本职责中**尚未验通**、有证据且可完成的一个用户可感知闭环；避开并行修改的文件。
3. 追完整链：现场事实 → 角色自己的决定 → 执行 → 业务结果 → 回执/存档 → 下一轮；程序不替角色决定语义、策略或假装成功。
4. 修真正根因，补必要回归；提交前刷新文件 SHA；没有设备证据就保留“待真机”，转做可离线验证的另一项，禁止刷文档和 Issue 凑完成量。
5. 只报告 **ID、分支、实际代码和测试、提交/CI、尚缺的真机/模型证据、下一验证动作**；完成项从 §二移除。JVM、APK、真实设备、模型与跨日分别验收。
