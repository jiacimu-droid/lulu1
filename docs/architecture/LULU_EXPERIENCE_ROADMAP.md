## 四、人物与社交的真实验收样本

优先采用获授权的脱敏真实回合，覆盖：普通玩笑/分歧、疲劳与学习压力但未请求方案、明确详细求助、用户纠正、条件改变、工具失败、持续约定跨日、角色分享/邀请、放下与重新考虑私人愿望。

同一人切私聊、电话、群聊、后台、日程、游戏和视频，核对完整输入、配置与模型连接、所选意图、真实工具参数、逐步结果和下一轮。额外使用主动/克制等对照人设；不把所有角色统一为热情、温柔或责任型。用户原话、角色原话、听见别人的话、私人心理和未证实状态严格区分。

社交另验：双方独立收发与想法、关系方向不对称、真实共同话题、邀约接受/拒绝/另约、到场/失败和各自后续。不能用每日固定发帖数或互相唤醒制造热闹。居民地点分布按实际日程和身份职责判断，不能硬编码搬家。

## 五、验收与交接规则

1. 开始接力读最新 main 的 AGENTS、此看板、人物进度和相关源码；先核对最后含测试的 CI。
2. 先处理看板最高优先的剩余工作；已完成代码只在新证据出现时再改。只做文档整理时明确记录整理范围。
3. 修复沿同一人物主循环和原权威 Store，复用已有调用/日程/工具反馈；不新增无意义常态收费轮次。
4. 仅提交现有 main，提交前检查并行窗口改动，不强推、不建分支/PR/Issue。
5. 修改 app/scripts/preview 后运行原索引生成器；仅本大纲/AGENTS 等非索引文档整理可按仓库规则跳过。
6. 依次报告源码/契约、单测/集成、APK/产物、真机、真实模型、跨日结果。取消或待运行 CI 不算成功。
7. 完成独立项后：在专项进度写证据与验收层级，再从待办删除；部分完成则只保留具体剩余工作，固定 ID 不另作他用。
8. 新交接写日期、基准 SHA、任务 ID、根因/修改、验证结果、未验风险与下一入口。历次流水记人物进度，此页只维护最新状态。
