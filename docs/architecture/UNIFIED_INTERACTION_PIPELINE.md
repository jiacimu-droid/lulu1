# 统一互动感知与人格线路

> 人格只有一份。电话、私聊、群聊、数字世界/见面、后台不是五个拥有不同心理的角色，而是同一角色在不同渠道收到真实线索，并选择不同的表达和行动通道。

## 唯一事实入口

- `SharedExperienceTimeline` 是事实与时间、渠道、原始来源的权威记录。通话结束、通话已识别/未识别、数字世界到访、真实聊天，都应各有稳定 evidenceId。
- `InteractionSignalBridge` 是**设备/交互动作适配器**，目前实现了电话长时间未确认语音和真正结束通话的信号。它仅陈述可观测事件，不能宣布用户生气、困倦、离开或有意冷落。
- 后续如果接入点击、离开页面、未读/已读、游戏共同经历和物品交互，新增的是这个层的**事实适配器**，而非新的人格模块。不能把无证据的后台技术状态误当作用户行为。
- `CharacterPerceptionContext` 是跨渠道**唯一新刺激汇聚入口**：抽取有权限的、人物真正可以观察的事件，结合直接收到的聊天输入，通过 `PerceptionStimulusLedger` 按 evidenceId 消重，用 `PerceptionStimulusResolver` 合并同时存在的多个线索。不得用轮询时间当新事件 ID。

## 同一人格处理

1. **发生：** 输入是客观事实和连续场景（发言、真实动作、未被确认的新语音、通话结束等），不能从没有事件推断新动作。
2. **理解：** `CharacterDecisionProtocol.principles` 提供所有角色场景共用的评估原则：事实、推测、关系、动机分开。一个长久的空白可以被注意到，但解释因性格和历史不同。
3. **变化：** `PrivateStateDeltaEngine` 检查真实新增的感受、矛盾或目标；`CharacterInnerLifeStore` 记录持续私有心理；`CompanionPresenceStore` 是在“此刻”查看的唯一投影，不再存通话专属的情感副本。
4. **决定：** `CharacterDecisionProtocol` 决定表达还是安静；后台由 `ProactivePerceptionRuntime` 选择真实能力；外部动作必须经 `CompanionActionRuntime` / `ToolRouter` 验证，只有回执才能入库。
5. **表达：** 电话保持整轮 TTS、文字聊天使用气泡、群聊有人称隔离、见面有动作与空间约束。它们只改变呈现形式和可执行能力，不改变人格、记忆与情绪来源。
6. **连续：** 事件携带 evidenceId，以原始时间线为依据；删除源事实时可清理派生内容。无新的变化不应重复写“她还没回我”的同义心声。

## 同次理解、取舍与行动：一个角色一条主决策线路

- **正常聊天、电话、群聊与见面**：本轮角色决策同时考虑事实、情绪、并存的主观可能、真正想继续关注的问题和此刻如何回应。保存有证据的心理变化、私人挂心、自我修正；对外表达只呈现角色愿意说的部分，不展示思维步骤。
- **通话结束、数字世界到访、触碰及后台生活**：交给 `ProactivePerceptionRuntime` 的**同一次自主行动决策**，在一次响应中选择 `action`、`appraisal`、`innerLife` 和可选 `pendingConcern`。**不再先调用「对真实互动的个人理解」然后再调用行动模型**。
- **思想不等于心事**：短期感受、多个互有张力的解释可以同时存在；只有对角色仍有意义、值得未来继续处理的核心问题才建立一条挂心。相同主题续想时沿用 `threadId`，避免“心疼/改变/补偿”被误造为三个独立任务。
- **行动与结果**：一个挂心的 `possibleNextStep` 只是可修改的行动设想。今后在实际情境中由角色自主选择是否做、如何做；只有真实执行器回执能更新 `lastOutcome`，不能把道歉、飞吻或日记直接当作“关系已经修复”。
- **长期成长**：`CharacterDevelopmentRuntime` 只负责跨多次真实经历形成较稳定的兴趣、表达/关系习惯等，另行合并总结有模型成本，但延后到聊天和通话空闲后进行；**不能替某次争吵决定角色当时的感受**。
- **成长轨迹**：`CharacterGrowthTrajectory` 显示用户反馈、当次真正出现的自我修正和有分量的取舍、持续挂心、已执行行动以及多证据形成的习惯。不把简单的聊天理解当成长，不把主观打算冒充已兑现事实。删除源记录时撤回关联证据。
- **回复优先**：真实未读用户消息的决策必须优先执行。背景人格加工既不能抢占聊天模型，也不能在格式失败后结束原本应该处理的新消息。未收到用户新内容时，模型仍可选择独处、安静或自主活动。

挂断后仍可以由 WorkManager 提供一次**自主行动机会**，但这是正常的单次行动决策，而不是强制经历两次独立的主观反思。设备后台调度不是实时保障；主动感知关掉时不自行发起新反应。

## 当下动机：同一决策，不是各页面的新规则（2026-10-13）

这次补充的是**执行前约束**，不是给出门等单项动作加提示词：

1. 统一事实源（`SharedExperienceTimeline`、`CharacterPerceptionContext`）提供可观察的当下情境；过去记忆与持续人格提供背景。
2. 各个响应入口沿用 `CharacterDecisionProtocol.principles`，角色先产生自己的解释、情绪或普通愿望，再作出一个选择。小小的「想出去吹风」「继续读」「有点烦不想回」都是有效当下动机；不强制新增心声和长期目标。
3. `CharacterBehaviorMotivation.resolve` 从角色**已生成**的 `reason`、`appraisal.responseAim`、与当前动作匹配的 `ownActivity.whyNow`、`innerLife.emotion.impulse` 等字段提取短依据；不能从工具结果倒推出曾经有某个想法。也不允许用「想读书」替代「为什么发朋友圈」。
4. `CharacterInnerLifeStore.recordCausalTransition` 在各渠道记录原始 evidenceId、选择和 `actionBasis`（短理解、感受、打算及其来源），但没有新心理变化不强迫生成 `innerThought`。
5. **执行前**，后台自主活动与私聊/电话/群聊附加工具统一校验动机。没有角色本人依据就拒绝执行而保留失败回执；数字世界见面 `moveTo` 无依据时不进行跳转。聊天和见面的普通口语仍由各场景自然表达，不为了检查而增加一次模型调用。
6. 后续行动只以 `ToolRouter` 或真实见面/世界状态回执为准。既有 `CharacterActionFeedback` 把选择原因和成功/失败交回角色下一次感知；曾经想过不等于做成。

**入口对应：** 私聊/电话 `LuluDeviceToolBridge`，群聊 `GroupEnsembleReplyEngine`，见面 `DigitalWorldMeetingGenerationV2` + `DigitalWorldMeetingRuntimeV2`，后台/世界 `ProactivePerceptionRuntime`，真实世界相遇及生活事件的自发表达 `AutonomousSocialRuntime`，延迟私生活动作 `CharacterSelfActivityRuntime`。各自保留不同的音频、消息、场景协议，但不能脱离共享的人格-动机-反馈链。

**边界：** 这一层确认「有没有角色亲自形成的选择依据」，并不能只靠字符串判断一个理由是不是符合性格、是否自相矛盾；这需要继续结合情境、记忆和实机行为验收，不应伪称程序已具备完美心理学判断。

## 电话闭环

- 直播电话中：根据最后一次**成功确认**的用户语音时间观察静默。麦克风触发噪声不能重置这项时钟。持续空白按 1/5/15/30/60 分钟及之后的小时段归档，每个段只留一个证据，不强制回复。
- 挂断后：存一条通话结束的**确定事实**，工作队列提供一次后续个人感知机会；不自动发送“为什么挂电话”，不强制出现担忧，也不让角色假装听到没转写成功的内容。角色可独立选择自己在意与否、沟通或继续别的事情。
- `CompanionPresenceDialog` 把**刚发生的客观互动**和**模型实际形成的心声**分开显示。后者必须在模型作出有依据的内在更新后才出现。
- 只有在角色的主动感知开关开启、模型可用、Android 后台工作得到执行时，挂断后才可能产生新的自主反应；WorkManager 不是毫秒级实时保障。

## 已接入与后续边界

- 共用输入入口：普通私聊/电话（`LuluDeviceToolBridge`）、主动/后台感知（`ProactivePerceptionRuntime`）、群聊角色回合（`GroupEnsembleReplyEngine`）；见面回复读取同一真实观察及同一决策原则。
- 目前不同场景**输出协议仍保留**：电话一句话及发声、群聊多人结构、见面的时序与空间约束并不能用一个同构输出 JSON 代替。统一的是输入语义和主体状态，不是强行把所有呈现拆成一个大文件。
- 进一步扩展用户进入/退出页面、已读行为、其他游戏中的物理接触时，应先检查是否真有可观测的、已授权事实；依照 `InteractionSignalBridge` + `CharacterPerceptionContext` 扩展，不能增加对应的“用户做 X，角色必须说 Y”固定脚本。

## 验收场景

- 通话持续有噪声但无法成功识别用户发言：角色知道“未收到确认内容”，不会断言用户一直安静，也不会被噪声清空记忆时间。
- 角色在讲话、用户只是停下来：可以有自己的新心声，但不必每隔两分钟刷一句催答。
- 用户主动挂断：生成事实记录和一次独立的后续判断机会；是否联系由个人意愿与现实权限决定。
- 之后回到群聊或数字世界：旧通话经历仍由同一条人物时间线检索，其他角色不能读取不属于自己的私聊秘密。
