# 模型理解与约定执行：2026-10-16

本次修复的原则：语义由角色模型结合完整上下文理解；程序负责结构、权限、记录、时钟与真实回执。不能根据几个词把普通想法升级成愿望，或把愿望升级成已经接受的责任。

## 正式路径

- 私聊、群聊及电话的既有主决策请求增加 `commitmentChanges`；无变更明确返回 `[]`。与已有 `innerLife.thoughts`、`innerLife.motives`、`appraisal.pendingConcerns` 区分，仍是同一个角色的判断。
- 提供真实当地时间、时区、旧任务的准确 ID、目标、时间与状态；模型理解“凌晨说的明天”“不是那个日期”等语境。程序不按关键词固定加一天，也不把“等会儿”固定换成若干分钟。
- 模型决定创建、修改、取消或完成后，通过原任务存储及闹钟执行器落地。修改必须明确选中旧 ID，不再由程序猜第一个或唯一任务。
- 真实保存回执交给私聊表达层与工具结果回复，不能把决策草稿当保存成功。电话保留原有单次流式表达，需避免在尚无回执时口头声称已完成。
- 同一真实输入批次记录已处理标记，普通主模型输出完整时不额外调用约定提取模型。旧生产者、缺少结构的输出保留一次有节流的语义恢复；恢复也不再依靠关键词门槛或固定时间解析。

## 持久化与展示

- 持续监督/责任可以没有固定闹钟时间。由模型指定类型和必要条件，保存为持续跟进，不强迫所有想法变成闹钟。
- 约定创建及修改后同步现有辞海词条；执行时间、旧闹钟取消及新闹钟注册由同一任务处理。原有任务、角色、记忆均不迁移或清空。
- 持续跟进在辞海不再显示成“已经触发”或“等待确定时间”。修正来源也关联到任务，删除来源可撤销派生责任。
- 修正直接工具创建的无会话来源任务被误判为“来源会话已删除”的问题；群聊来源ID与正常消息ID匹配时正确处理角色后缀。

## 验证范围

- 本地实际 Kotlin/JUnit：表达相关30项及约定结构验证4项通过，共34项。
- 新增 Android/Robolectric 验证：凌晨约定及日期纠正确实交给模型、持续约定落辞海、不凭空建闹钟、改期替换旧闹钟及同步原词条、错误ID无副作用、输入批次去重，以及真实主聊天链路无需新增提取请求。
- 模拟模型验证输入、路由和写入，不等于证明真实模型每次都能准确理解。完整 Android 测试和 APK 以现有 GitHub Actions 结果为准；真实模型多轮表现、真机到点提醒和用户体验仍需实际使用验证。
