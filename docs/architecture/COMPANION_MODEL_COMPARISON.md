# 陪伴模型：先区分表达、思考与执行

核对日期：2026-10-26。用户确认当前型号为 Gemini 4 Argon 和 Gemini 3.8 Flash。本轮没有密钥下的真实模型对比、手机延迟测试或中转费用实测，以下是官方能力与本仓架构的选型分析，不是效果排名。

后续实现更新：API设置新增可选“文字表达”存档，沿原现有表达阶段使用；不选时跟随本轮思考模型。直接一次决策发言的在线私聊、电话主决策继续原模型，不因此强制增加润色请求。Jev也已加入可选原生工具，详见 [JEV_DIRECTIONS_GUIDE.md](JEV_DIRECTIONS_GUIDE.md)；并未自动为主人更换任何厂商或型号。

## 按职责分别选型，不要求一个模型包办

主人进一步明确：不同环节可以分别选模型。连续人格、关系和记忆仍来自本仓同一角色的权威状态，不要求所有环节使用同一供应商或型号。下表描述核对到的真实路由，不将将来可扩展的配置写成已完成能力。

| 职责 | 当前实际配置与路径 | 评估重点 |
|---|---|---|
| 听懂声音，转为文字 | `CallVoiceConfiguration` 的 STT 选择独立于TTS，已有本地Whisper及云端路线 | 中文、名字、打断、延迟与识别费用 |
| 理解、思考与行动决策 | 当前Chat档案；电话的 `ModelUsage.VoiceCall` 也解析到Chat档案 | 上下文理解、人格/目标连续、多行动及真实回执使用 |
| 写出自然台词 | 前台部分路径已有planner→expression分工；表达存档可单独选择，未选时跟随本轮连接。其他入口可能一次决策直接输出文字 | 口语、人物差异、接话节奏与不重复，不以工具跑分替代 |
| 观察图片、屏幕和摄像头 | `VisionModelService` 有专用识图配置，部分路径未配置时回退Chat | 真实可见内容、来源时间、错误与不确定性 |
| 把台词说出来 | TTS独立选择服务/型号及人物音色，MiniMax、ElevenLabs和系统路线沿现有设置 | 音色、情绪、自然停顿、稳定性及真实音频延迟 |

因此“思考用一个模型、文字表达用另一个模型、声音再用专门模型”可以作为后续组合方案评估；现已提供可选表达存档，沿原已有阶段分工；未改变电话主决策跟随Chat的现行设置，也不为一次直接发言新增润色轮次。下面三款文字模型的比较只针对其文字与决策能力，不代替ASR、TTS或视觉的独立选型。

|---|---|---|---|
| Gemini 3.8 Flash | 快速、成本效率及复杂代理；百万级输入，文字输出，工具调用/结构化输出 | 日常私聊、电话文字决策主力候选；接话及时性、多轮不重复及原工具协议 | 实际首字/整轮延迟、人格保持、主动想法多样性、真实工具成功率；不能由Flash名称推断一定更口语 |

## 怎样比较才贴合“数字生命”

1. **自然表达与陪伴分寸**：同一角色、相同记忆和关系、相同输入；看能否顺着话接、什么时候听而不急着安慰、不固定问句收尾。不能只挑一句甜话打分。
2. **本人想法**：是否保留独立偏好、矛盾和未尽念头；下一轮能结合新事实改变看法，避免每轮重复人设标签。不同角色不应被评成同一温柔模板。
3. **记忆与时间**：明确自述、旧印象、后来纠正分别使用；不把旧画面当当前事实，不把本人想做当双方约定，不编造没发生的共同经历。
4. **实际行动**：对“说一句再放歌、之后写自己的记录”等组合，检查原执行器各项真实回执；搜索失败、权限撤销、物品不存在时，不谎称完成。不按文字中是否出现“做了”计成功。
5. **长期连续与费用**：同一个多轮过程对照，记录人格漂移、重复、来源混淆、有效行动数、首字/整轮延迟和真实中转账单。保持同一输入预算，并记录网关到底返回哪个型号；官方按token报价不代表用户按次中转成本。

可复用情境包括：轻松的“喂”、明确“先听我说别安慰”、角色同时想亲近又顾及边界、先前理解被用户纠正、工具失败和视频共享关闭重开。记录原输出和实际回执，不预填理想回答或虚构分数。

## 当前取舍与接口边界

目前建议先把3.8 Flash作为日常主力候选，Argon作为复杂推理/行动的对照；这是根据官方定位的推断。若Argon在同角色盲评中更自然且延迟可接受，也完全可以作为日常主力。最终以用户的多轮体验和真实行动证据决定；本轮保留原网关与用户模型；新增的表达分工由主人显式选择，不按输入关键词猜供应商或新建第二套人格。Jev也是显式启用后由本人选择的工具，不作为每轮默认评判。

两款Gemini均支持多模态输入，但官方接口文字输出、均不支持Live API或原生音频生成；不能仅换聊天模型就宣称升级了实时语音。3.8 Flash的thinking支持low/medium/high，minimal不支持。当前本仓兼容网关使用原messages等协议，未验证中转支持前，不添加供应商专属推理参数或借调采样参数保证“更有人味”。
