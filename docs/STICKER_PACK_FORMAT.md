# Lulu1 表情包整组导入

Lulu1 的表情包在聊天面板 → 表情包 → **＋** 中管理。支持直接一次选多张相册图片、导入 ZIP 整包、导入 JSON/CSV/TXT 清单或粘贴链接。图片保存到 App 私有存储，聊天不依赖外部图片链接长期有效。导入本身**不触发识图收费**。

## 格式一：推荐分享 ZIP 整包

可以把几十张 PNG/JPG/GIF/WebP 图片放进一个 ZIP，名称即默认分组名：

```text
猫猫日常.zip
  抱抱.png
  偷笑.gif
  不理你.webp
  manifest.json       （可选）
```

如果已经整理好描述，在 ZIP 根目录放 `manifest.json`：

```json
{
  "pack": "猫猫日常",
  "items": [
    {
      "file": "抱抱.png",
      "name": "猫猫求抱抱",
      "description": "一只白猫张开前爪，圆眼睛看向前方。",
      "usage": "撒娇、安慰、求贴贴"
    },
    {
      "file": "偷笑.gif",
      "name": "猫猫偷笑",
      "description": "第一帧：一只猫咪捂着嘴，眼睛眯起来。",
      "usage": "得意、偷笑"
    }
  ]
}
```

- `file` 对应 ZIP 中的图片路径；`name` 是短名称。
- `description` 记录实际可见的画面；`usage` 是社交场景，不是视觉事实。
- 没有 `manifest.json` 也能整组导入，默认以文件名命名，描述为空。
- 图片最多 5 MB / 张，ZIP 解压总数据最多 80 MB，单包最多处理 320 个文件；个人图库上限 220 张。重复的同内容 ZIP 图片不会重复存入图库。
- ZIP 图片在手机本地解包，不需要联网或调用 AI。

## 格式二：链接清单

当整理者没有打包图片，只提供直链时，支持 JSON、CSV、TXT 以及一行一条的链接清单。

```json
{
  "pack": "猫猫日常",
  "items": [
    {
      "url": "https://example.org/stickers/hug.png",
      "name": "抱抱猫",
      "description": "小猫伸出前爪，像要拥抱。",
      "usage": "求抱抱"
    }
  ]
}
```

TXT/CSV 可写为：

```text
https://example.org/a.png | 亲亲 | 猫猫嘟嘴 | 示好 | 猫猫日常
https://example.org/b.gif | 震惊 | 猫猫眼睛瞪圆 | 惊讶 | 猫猫日常
```

链接必须是可直接获取 PNG/JPG/GIF/WebP 图片的公开 HTTPS 地址，不能是展示图片的普通网页。单份清单最多 200 张，下载后保存为本地素材。

## 可选识图

导入后，可在当前分组点击「批量识图」。**仅主动点击确认后**使用识图设置中独立配置的视觉模型，按 4 张一批发起请求，返回画面描述、名称和语气建议；已有描述的图不会再次识图。没有独立配置时不会自动调用聊天模型，失败时不会自动重试可能已经扣费的调用。实际费用由模型与中转平台决定。

一般聊天时角色只拿到已经保存的文字描述和实际存在的表情包 ID，因此即使聊天模型不支持多模态也可以选用表情包。没有经过描述的图片仍能由用户本人发送，但角色不会编造自己看到的画面。
