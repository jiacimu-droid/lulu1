# Lulu1 表情包整组导入

Lulu1 的表情包在聊天面板 → 表情包 → **＋** 中管理。**优先直接选择 Word（.docx）图文文档整组导入**，也支持相册批量选择。ZIP 整包、JSON/CSV/TXT 清单或粘贴链接是补充兼容格式。图片保存到 App 私有存储，聊天不依赖外部图片链接长期有效。图片与文字描述会分开保留；**已经有描述的表情不重复识图**。

## 首选：Word 文档（.docx）一键整组导入

别人整理好一个 Word 文档，里面直接插入一组表情包图片，每张图旁边写名称、画面描述、使用语气即可。用户无需拆图、制作 ZIP 或手写 JSON。

示例 Word 内容（其中图片是实际插入的图片，而非这些占位文字）：

- [猫猫抱抱图片]
  - 名称：抱抱猫
  - 画面描述：一只猫张开双爪向前拥抱
  - 使用场景：求抱抱、安慰
- [猫猫生气图片]
  - 名称：气鼓鼓
  - 画面描述：猫咪皱眉、嘴巴下弯
  - 使用场景：小生气、哼

进入聊天的表情包 → ＋ → **导入 Word 文档（推荐）**，选中 .docx 文件即可整组导入，文档名默认作为分组名。

- 支持 Word 文档**内嵌图片**，以及仅整理了 HTTPS 图片直链和说明文字的 Word 文档。
- 文档已有描述可直接保存；没有描述也能存图，随后可以主动选择批量识图。
- 识别紧邻图片的「名称：」「画面描述：」「使用场景：」等文字。
- 旧二进制 .doc 文件不直接解析，请先在 Word/WPS 另存为 .docx。
- 单张 5 MB、整份 Word 解压总量 80 MB、个人图库总量 220 张。

## 备选：ZIP 图片包（不是主要入口）

可以把几十张 PNG/JPG/GIF/WebP 图片放进一个 ZIP，名称即默认分组名：

```text
猫猫日常.zip
  抱抱.png
  偷笑.gif
  不理你.webp
  manifest.json       （可选）
```

如果已经整理好描述，在 ZIP 根目录放 `manifest.json`：

```json
{
  "pack": "猫猫日常",
  "items": [
    {
      "file": "抱抱.png",
      "name": "猫猫求抱抱",
      "description": "一只白猫张开前爪，圆眼睛看向前方。",
      "usage": "撒娇、安慰、求贴贴"
    },
    {
      "file": "偷笑.gif",
      "name": "猫猫偷笑",
      "description": "第一帧：一只猫咪捂着嘴，眼睛眯起来。",
      "usage": "得意、偷笑"
    }
  ]
}
```

- `file` 对应 ZIP 中的图片路径；`name` 是短名称。
- `description` 记录实际可见的画面；`usage` 是社交场景，不是视觉事实。
- 没有 `manifest.json` 也能整组导入，默认以文件名命名，描述为空。
- 图片最多 5 MB / 张，ZIP 解压总数据最多 80 MB，单包最多处理 320 个文件；个人图库上限 220 张。重复的同内容 ZIP 图片不会重复存入图库。
- ZIP 图片在手机本地解包，不需要联网或调用 AI。

## 格式二：链接清单

当整理者没有打包图片，只提供直链时，支持 JSON、CSV、TXT 以及一行一条的链接清单。

```json
{
  "pack": "猫猫日常",
  "items": [
    {
      "url": "https://example.org/stickers/hug.png",
      "name": "抱抱猫",
      "description": "小猫伸出前爪，像要拥抱。",
      "usage": "求抱抱"
    }
  ]
}
```

TXT/CSV 可写为：

```text
https://example.org/a.png | 亲亲 | 猫猫嘟嘴 | 示好 | 猫猫日常
https://example.org/b.gif | 震惊 | 猫猫眼睛瞪圆 | 惊讶 | 猫猫日常
```

链接必须是可直接获取 PNG/JPG/GIF/WebP 图片的公开 HTTPS 地址，不能是展示图片的普通网页。单份清单最多 200 张，下载后保存为本地素材。

## 兼容不同整理格式

TXT / CSV / Word 文档可以以各种顺序放置「图片链接、标题、真实画面描述、用途/语气、分组」。解析器按实际 HTTPS 图片链接识别每一条图片记录，并尽量关联相邻文字；支持标题在链接前、链接在标题前、用 `|`/制表符分隔的表格，以及带引号的 CSV。Word 可同时包含实际插入的图片与图片链接，且支持图片前或图片后的说明。

**没有明确描述就保持为空**，不会把标题或情绪臆测为看过图片。错误链接仍会提示失败；内容歧义较大的特殊模板可能需要人工检查和调整，无法保证任意第三方排版百分之百准确。

## 识图路由（一次选择，后续自动执行）

在聊天表情面板的整组导入菜单中可以给**当前角色及当前聊天模型**选择识图模式：

- **关闭**（默认）：只用文档里原本的画面描述；用户仍能正常发无描述的图片。
- **聊天模型直接看图**：如果当前角色选用的模型支持多模态，**在原本这一次角色聊天请求中**带上最多两张没有描述的本地候选表情图。模型可根据真实像素决定是否发出；不调用另一条独立识图 API。图片仍会计入普通聊天的视觉输入成本，因此不应反复上传整组图。
- **独立识图模型自动补描述**：用户明确启用此付费模式后，每次整组导入完毕，**仅对还没有描述的图片**按最多四张一批调用已配置的视觉模型。识别结果保存到图库，以后普通文字模型直接读取描述即可，无须每轮重新看图。为避免网络超时导致悄悄重复扣费，每批自动尝试一次，失败保留提示，不自动无限重试。

聊天模型的多模态能力不能仅凭它有模型名称或 API 地址来保证，因此「直接看图」需要为当前角色当前模型启用；更换模型后原能力声明失效。没配置独立识图模型时不会偷偷将自动批处理切到其他收费 API。角色只能发送图库中真实存在、原图可读的表情。

**费用提醒**：多模态聊天虽然不额外增加 API 次数，仍可能增加当前请求的图像 token 费用；独立模型自动识图则产生额外请求。两种模式不会同时对同一批表情重复识图。具体价格取决于用户模型与中转站。
