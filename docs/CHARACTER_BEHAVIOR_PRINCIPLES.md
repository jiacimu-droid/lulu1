# 角色活人感：原则、模型判断、程序契约的边界

2026-10-09：以**可跨情境复用的原则**替代「用户举一个例子就写一条硬规则」。

## 三层架构

1. **人格／原则层**（`CharacterExpressionGuide`、角色个人资料、`CharacterSpeechIdentity`）
   - 角色有稳定价值与关系边界，但成熟思想不等于捏造已活过的经历。
   - 感知与已有主观状态决定注意力、表达意愿，再产生真实聊天节奏、标点、语气词、玩笑、沉默和动作。
   - 社交模仿是可选行为，含关系意图、接收者反应与修正；不能按「连续四条短信」「N个哈哈」之类的量化条件硬触发。
   - 从真实见闻学到语言，模仿／尝试／重复自用／形成习惯分级处理，并留证据来源。
2. **能力与事实层**（行动执行器、共享时间线、阅读／游戏／世界状态）
   - 行为必须有可执行目标；结果由程序和回执确认。
   - 日记、感想、人物台词是**主观表述**，小说场景不等于亲历。
   - 日常阅读、游戏、社交、数字世界事件、现实资料与独处思考均可能影响后续选择，但不能空转时伪造经历。
3. **精确合约层**（JSON 解析、有效 ID、权限、语音接口、错误恢复）
   - 这是应当保留的规则，不可抽象掉：字段名、权限验证、私密信息防泄露、记忆源删除/撤销、连续状态和工具执行回执。
   - 具体示例只作启发，不写成「看到 X 必须 Y」。添加新特例前，先检查是否可由现有原则、记忆和上下文表达。

## 具体原例应该如何迁移

- 连续短气泡 → **谈话节奏与亲密调侃**，不是四条以上必须模仿。
- 一串「哈哈哈哈」 → **情绪强度可借字数、标点、短气泡表达**，不是按照哈哈数量判定开心值。
- “我去／哈基米／谐音梗” → **真实接触后的文化词汇与当场戏谑能力**，不是统一写进世界书的台词。
- 阅读 → **真实段落、真实进度、角色自己的理解和下一步愿望**，不强行变成生活经历、立刻拥有主角的全部阅历。
- 3D 房间中看到掉落事件 → 先有可验证的世界事件，再产生人物视线、语音、情绪与动作；不靠提示词假装物件掉落。

## 新功能验收顺序

人物是否有独立性 → 能否准确读取时间线与现场 → 选择是否真的行动 → 工具是否执行与保存 → 下一轮是否承接真实结果 → 在不同场合的表达是否仍是同一个角色。

反例测试应当覆盖：角色不跟风模仿、玩笑被误解时停止、没实际读过的章节不影响经历、用户明确边界优先、表达某事不等于行动完成、未授权者不能读取私聊。
