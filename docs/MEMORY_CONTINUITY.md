# 角色记忆连续性

## 存储与兼容

原始时间线仍是 SQLite 证据底座；记忆正文、即时提取检查点与删除来源标记继续保存在现有 lulu_memory_store。增加 Core、Stable、Episode 层级及 subject/slot。旧存档中没有层级的 Fact 默认 Stable，其余默认 Episode；旧固定条目也按核心记忆处理。保留原有保护区、批次设置与备份入口，不清空旧数据。

辞海增加 Active/Resolved/Archived、来源事件和最近回访时间。旧条目默认 Active。约定执行继续由 CommitmentTask 系统负责。

## 提取

- 用户的重要记忆、偏好、边界信号只触发上下文模型判断，不直接按关键词写事实。明确稳定信息即时保存，无需攒满批次；临时条件、引用、假设和虚构剧情不升级为长期事实。
- 重要长期边界、关系和安排可进入 Core；普通喜好为 Stable。角色答应行动不证明执行成功。
- 即时检查点与批量检查点独立持久化；网络失败和格式错误保留重试机会，来源删除/修改会撤销对应检查点和派生记忆。
- 普通内容仍按现有批次整理。静默十分钟后自动处理包含保护区的尾批；手动整理可直接处理不足一批的记录。
- Fact 不再凭高字面相似度合并，防止一个否定词反转偏好后被当作重复项。完全等价记忆合并时保留核心级别和来源。

## 上下文与召回

- 所有有效 Core/固定记忆走独立上下文，不占普通召回条数，没有普通条数裁剪。仅在相关时自然使用；最新明确纠正优先。
- 普通候选扩为 128，统一召回默认最多 96，正文按约 9000 字符预算选取，长条目放不下时继续尝试后续短条目。字符预算是保守成本估算，并非精确 tokenizer。
- 关键词、向量、时间范围和可选重排共同召回。向量冷启动时可提出纯语义候选，额外的小模型核验其相关性；核验失败降级到有独立依据的候选。
- 原始记录按话题与日历时间回查，覆盖提取失败或未形成摘要的相关信息，不把全部积压塞进每轮上下文。删除/禁止回忆/已替代记忆的来源不通过这个入口恢复。
- 核心记忆、当前生活、未解决挂心及责任独立于日记/收藏的相关性预算。日记、收藏、已解决条目仅在话题相关时进入历史上下文。
- 活跃责任仍来自任务 Store；挂心解决必须有用户明确反馈，未回复不能当作解决。辞海支持手动标记解决/重新挂心。

## 恢复与限制

向量索引监听记忆变化并定期补偿：更换向量模型、启用开关或索引失败后会重试。事实替代失败/格式异常不再标记成功，定期重新判断，并在写入前核对条目仍存在。

即时提取和纯语义核验会增加小规模模型调用。核心记忆不因普通配额被裁剪，用户积累非常多核心内容时输入成本会相应增长。Android 进程被终止时不能继续执行应用内计时轮询，重启后会恢复检查与尾批整理。

新增行为测试覆盖：超过12条核心记忆、短条目容量、超长条目跳过、即时提取失败重试和重启检查点、删除/禁用防回查、挂心不被日记挤占、状态持久化、相反偏好保留、静默时间边界和跨年月检索。

## 2026-10-28：跨场景经历的原始证据链（借鉴叙事记忆，但不创建影子叙事库）

真实事件仍在唯一 `SharedExperienceTimeline`。在现有 `UnifiedMemoryOrchestrator` → `MemoryEvidenceSelection` 和 `MemoryWorkingSet` 的召回路径中，`NarrativeEvidenceChain` 以**同一人物、同一非空 taskId** 串起跨私聊/电话/定时活动/工具回执的前后记录（可以相隔多天）；若没有 taskId，则仅对同一明确 sessionId 中时间相距不超过 15 分钟的邻居提供较弱的上下文。任务链优先收取近邻和后续原始 ToolResult，但**“角色说过/承诺”绝不等于执行成功或主人满意**。原文、时间、证据类型和 eventId/revision 仍单独显示；事件链标签只代表显式编号相关、按时间排序，不生成不存在的原因、意图或结果。

只从原始事件当前 revision、已授权可召回、当前时刻之前的证据构建投影，删除、撤回、记忆禁回和编辑后必须在下一次查询立即消失；不增添持久化剧情摘要、第二套 Memory Store、自动修改人格/目标或额外 LLM 调用。大量命中的单次提示词会为强 ID 关联的实际后续结果保留有限位置，未用位置归还排名原始命中。原始 SQLite 历史不限制数量，不因 prompt 字数预算而被删掉。

自主角色 `CharacterAssociativeRecall.render` 也使用相同投影，**只在原来已经读取的最近 160 条原始事件中**提供关联后续事件，不扩大自主醒来每轮的长期扫描；长期旧事仍通过统一关联召回按需查证。这不是“霍克斯过程”或额外的周期性统计调用。

回归：同任务跨数日/跨场景、同会话不同频道但严格时间窗、不同角色隔离、旧 revision/撤回事件不再出现、真实回执优于大批不相关命中、提示词字数预算、原始数据不变；Robolectric 验证从 SQLite 读回源记录，经统一召回进入 compact 和 full 工作集，再删除回执检验两条路径都不再使用。测试和正式 APK/真机状态以对应 CI 为准，不能将源码已提交视为真机验收。

**后续能力**：真正按人物主观理解整理“这段经历给自己留下怎样的认识/仍然在意什么”应复用已有 `CharacterDevelopmentRuntime` 低频学习与 motive/innerLife 的同轮决策，并引用具体事件版本；当前仅保证事实关联，不由程序替人物判定因果。缺少共享 task/session ID 的异场景事件不会因为文本相似就被当作同一件事，需另行研究源 ID 交接，不得靠关键词强制串线。
