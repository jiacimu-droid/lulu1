# 统一人物模型与电话体验修复

## 为什么不是继续堆人格标签

本次研究参考的是人格科学中的整合与情境观点，而不是为角色强制分型：

- McAdams 与 Pals（2006）将人格描述组织为相对稳定的特质、与生活背景相关的适应方式，以及自我理解的生命叙事，并考虑文化和社会情境。参考：[论文摘要](https://pubmed.ncbi.nlm.nih.gov/16594837/)。
- Mischel 与 Shoda（1995）的认知—情感系统理论关注同一个人在不同情境中有规律的反应差异。参考：[论文摘要](https://pubmed.ncbi.nlm.nih.gov/7740090/)。
- Fleeson（2001）研究了个人日常状态的变化与整体特质描述的关系。参考：[论文摘要](https://pubmed.ncbi.nlm.nih.gov/11414368/)。

以下是根据这些观点作出的应用设计，不是心理诊断，也不是已经验证的人类心智仿真。人格研究不会直接证明一个提示词或应用具有意识。

## 需要哪些信息

| 层次 | 需要说明什么 | 必要程度 | 应用里的来源 |
| --- | --- | --- | --- |
| 身份与生活基础 | 我是谁、处于怎样的世界、怎样的关系；实际拥有哪些能力 | 建立明确角色时必要 | 原角色资料、人设、生命形态、世界数据、能力目录 |
| 核心倾向与驱动力 | 重视什么，长期追求什么；发生冲突时优先什么 | 要有足够辨识度，原人设已经写明时不用重复填写 | 原人设及“价值与底线／想要与担忧” |
| 理解与应对 | 注意哪些线索，如何作判断；在拒绝、失败、压力等情境中怎样反应 | 细腻且稳定的行为模拟需要具体情境信息 | “理解世界与作判断／分歧、受挫与修复” |
| 关系与表达 | 面对不同对象如何关心、表达、靠近或保持距离；语言与情绪怎样体现 | 是陪伴体验的重点，但不强制所有角色亲密或温柔 | “关系与关心／不同情境下的样子／语言与情绪表达” |
| 连续经历与变化 | 发生过什么、做了什么、成功失败、纠正反馈、当前在意的事和后来的习惯 | 连续生活必须有，不能靠初始设定替代 | 共同时间线、工具回执、当前状态、承诺和成长记录 |

初始填写可以只用完整的人设文本。辅助项目不是必填表格；已经说清楚的部分不需要多次重复。未指定的兴趣、偏好或担忧允许根据实际经历逐渐形成，而不是让用户预写一生。

“最怕什么”是可选的动机线索，不是每个人都必须有一个核心创伤。荣格功能、九型或大五等词可以作为用户熟悉的描述参考，但不能凭一个类型自动补齐经历、价值观、恋爱方式或全部心理活动。声音、外貌、固定口头禅等会影响表现，但不能替代选择与行为的结构。

## 怎样把信息变成同一个人的行为

统一角色入口读取原人设、行为设定、当前状态、相关真实事件、成长记录和能力。模型结合当前情境产生角色的主观理解，再选择回应、行动、等待或保持安静。行动由现有执行器完成；失败与成功以程序返回为准。经历进入原时间线，经过依据校验形成后续习惯与判断。

“对外克制、对亲密伴侣放松”“强大但主动配合”“有共情也有独立意见”可以共存。需要解释触发情境与不变的价值取舍，不能按轮次随机切换人格，也不能每轮同时把全部侧面演一遍。

生成的心声、日记和自我叙述仍属主观表达，不成为事实证据。已执行动作、用户反馈和原始来源才可作为成长依据。当前心情不被直接保存成永久人格。

本次将用户行为设定加入成长约束快照：修改后，使用旧快照形成的成长暂不注入，历史仍保留；新更新必须对应当前人设和行为设定。事件版本、角色隔离、反例和重复经历检查沿用现有逻辑。这些程序检查不会保证模型的每句语义都绝无矛盾，实际人物效果仍需场景测试。

## 手机上的角色设置

四个分区：资料、人格、陪伴、管理。人格按驱动力、理解与应对、关系与表达、成长空间分组；点击行打开单项编辑，不再一页堆叠所有大输入框。旧字段保留原键，新增字段是增量存储，不清空旧人设或记忆。

名为江渡或江都的角色提供“填入江渡设定”：整理本次用户描述，只填写空白项，不覆盖现有内容。没有强制设定兴趣或虚构恐惧；保留安全感、浪漫、理性共情、审美、幽默、不同情境与自愿亲密的组合。

## 电话修复的实际原因与改动

此前普通电话依赖安卓系统 SpeechRecognizer 收音转写，所选 MiniMax/ElevenLabs 主要负责发声。手机即使已允许麦克风，也可能没有可用系统识别服务。同时独立的 ElevenLabs 实时开关能绕过声音供应商选择；第一句识别的临时字幕在聊天消息为空时被空态遮住，发声失败只提示 Toast，缺少持续可见的阶段状态。

现在：

1. 语音设置顶端先选 MiniMax、ElevenLabs 或系统语音；拨号页也可明确选择 MiniMax/ElevenLabs。MiniMax 不能进入 ElevenLabs Agent 线路。
2. MiniMax 直接录制真实单声道 16kHz PCM，形成合法 WAV，停顿后调用同区域 `/v1/speech_to_text`（`asr-1.0`）并显示 SSE 转写结果，再使用原电话模型及 MiniMax 发声。无需部署应用自己的服务。
3. ElevenLabs 账号直连使用 Scribe Realtime WebSocket (`scribe_v2_realtime`) 识别、原电话模型回复、所选 ElevenLabs Voice ID 发声；个人 Key 由手机配置，不随 APK 发布。
4. 只有明确选择“Agent 高级通话”才需要现有云端角色服务与 ElevenLabs Agent 配置。云端长任务仍是可选设置，不再作为普通电话的前置条件。
5. 普通电话显示实际麦克风输入强度、收音/识别/模型回复/发声的状态与失败信息，首句临时字幕也能显示。收音失败可重试，MiniMax 收音阈值可调。
6. 发声时普通直连路线暂时屏蔽识别输入，避免自己听自己；提供“打断并重新收音”。该路线不宣称已实现完整自动双工；完整 Agent 路线仍需独立在线验证。
7. 挂断或重试会取消录音、识别连接和旧回复；迟到的结果按会话和识别代数丢弃，已经完成的工具动作仍使用原执行记录。

官方协议依据：[MiniMax 语音识别](https://platform.minimax.cn/docs/api-reference/speech-to-text)、[MiniMax 官方调试台](https://solutions.minimaxi.com/debug/asr)、[ElevenLabs Realtime Speech-to-Text](https://elevenlabs.io/docs/api-reference/speech-to-text/v-1-speech-to-text-realtime)。MiniMax 的流式返回发生在上传音频之后，不能称作麦克风逐字实时输入。

只开通合成不代表识别权限或识别额度也已可用。账号不支持、余额不足或接口区域不匹配时，页面会返回真实失败。供应商音频质量、网络延迟、麦克风收音与回声仍需手机在线测试。

## 聊天状态与错误

任务开始到结束由原 ChatReplyTaskManager 跟踪，标题栏和输入区显示请求／生成回复状态，不谎称已确认远端模型收到。群聊显示当前角色。错误在当前聊天页通过即时 Toast 与短 Snackbar 呈现；余额、渠道、密钥权限、限频、网络错误做简明分类，保留经过脱敏的原因。每次错误有独立 ID，同一种错误再次发生也会重新提示；旧提示结束不能清掉更新的错误。

## 验证范围

规则测试覆盖供应商互斥路由、MiniMax 接口区域、WAV 格式与实际 PCM、错误分类及密钥脱敏、重复错误事件与旧提示清理、行为设定改变后旧成长约束失效。编译与测试结果另行记录。

真实 MiniMax/ElevenLabs Key 在用户手机中，开发环境没有在线测试账号；不以单元测试或构建成功冒充电话已在线验收。
