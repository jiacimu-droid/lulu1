# 露露机 Lulu

> 一个真正属于用户自己的 Android AI 陪伴应用。

## 项目状态

`lulu1` 是露露机的新项目，也是一次从零开始的独立重构。

这个仓库**不会通过修改说明文件，把旧项目的代码包装成原创项目**。旧仓库 `jiacimu-droid/lulu` 建立在 OrangeChat / RikkaHub 等既有项目基础上；新仓库会把它们仅作为功能需求和使用体验的参考，不直接整仓复制旧骨架。

新项目中的每个模块都需要满足以下至少一种情况：

1. 由本项目重新设计并独立实现；
2. 明确来自第三方开源项目，并完整遵守其许可证和署名要求；
3. 暂时无法确认来源时，不迁入正式代码。

详细归属记录见 [`docs/PROVENANCE.md`](docs/PROVENANCE.md)。

## 露露机想做什么

露露机不是普通聊天客户端，而是一个“生活在手机里的 AI 伴侣”。核心目标包括：

- 长期记忆、关系连续性和角色一致性；
- 手机桌面式界面与独立功能入口；
- 低延迟语音通话与主动联系；
- 学习计划、番茄钟、抽卡激励和考研工具；
- 责任与承诺记录、主动提醒和生活监督；
- 可持续维护的 Android 架构和稳定 APK 发布流程。

## 重构原则

- **不整仓复制**：不把旧仓库换名后继续使用。
- **功能逐块搬迁**：先写清需求和数据结构，再独立实现。
- **来源可追踪**：每个迁入模块都记录来源、作者和处理方式。
- **数据优先**：旧应用中的角色、记忆、设置和学习数据需要设计导出/导入方案。
- **保持可运行**：旧仓库在新项目达到可用状态前继续作为现有版本维护。
- **少而稳定的自动化**：只保留正式构建与发布流程，不创建一次性工作流。

## 第一阶段

当前第一阶段不是搬代码，而是确定新项目的边界：

1. 建立项目归属与迁移账本；
2. 盘点旧仓库中真正需要保留的功能；
3. 确定全新 Android 技术架构；
4. 创建最小可运行 App；
5. 优先重写角色、聊天、记忆与数据迁移能力。

完整路线见 [`docs/MIGRATION_PLAN.md`](docs/MIGRATION_PLAN.md)。
