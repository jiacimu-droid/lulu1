# 露露机游戏馆改版 · 设计审稿

范围以 `LuluGamesApp.kt` 的正式大厅为准。主推是「方块小岛、迷雾摸金」，还有「深海回声、记忆配对、海龟汤、快艇骰子」。下面的成长目标和新地图机制是设计提案。试玩地图使用当前 Kotlin 游戏状态；两款世界游戏的地图、开局和 HUD 已有可操作审稿。

## 大厅和手机布局

- **竖屏游戏馆**。顶部只有返回、标题和游戏记录。正在进行的岛屿、摸金和骰局显示实际进度及「继续」。两款合作世界用有场景的图卡；另外四款用紧凑入口。大厅保持现有深色场馆基调。
- **开局前**。方块小岛把继续岛屿放在新建之前，角色邀请是可选动作。摸金第一屏能看见难度、起始装备、队伍与出发。失败重试回到相同难度，改变装备再出发也容易。难度说明应写实际影响，例如守卫数、血量和伤害。
- **局内横屏**。地图占满，左手移动，右手一个随情境变化的主键和少量明确的战术键。移动只移动，瞄准与确认分开。左上只留目标、血量和少量核心资源，右上找语音与离开，完整行囊和配方按需打开。高风险动作带文字、轮廓和可听提示；文字放大后允许换行。横屏可按 844×390 和 740×360 先检视，方向区按钮以至少 44 px 为目标，避开系统边缘。
- **语音协作**。同一角色经现有游戏开放麦与 Full 人物决策接入。显示麦克风静音、队友在场以及已经执行的动作。标点和语音提供同一份现场信息，角色根据所见自行决定接受、拒绝或换方案。让玩家听得懂「还有多远」，同时看得见队友是否真的在路上、保护是否成功、材料进了哪里。队友执行实体动作产生独立回执，角色选择和回执都能进入既有共享经历。移动每格不触发模型。原生角色或语音不可用时仍可单人开局。
- **记录**。沿用独立全屏记录路线。一起玩显示真实结算，角色自己玩可查看原有实际过程回放。首页露出一次有意义的更新，详情留给档案。

## 方块小岛 · 3D 斜俯视

**美术和镜头**。清新、安静、有手作感。草绿暖木、浅潮水、蓝灰矿和夜灯。原型的方块有实际长宽高，模型由代码生成，近看能见松树、晶矿、工作台、钓鱼水域和小屋的结构；在「全岛」下转镜头看岸线和地形。正式方向是带遮挡处理的固定斜俯视档位，移动方向跟着摄像机转。建筑背面遮住人物时淡化屋顶，路与背景的装饰靠色阶区分。横版平视会丢掉房屋脚印和资源位置，第一人称会让手机同时控制走路、看向和施工，故采用少量固定旋转档位。

| 阶段 | 玩家在做什么 | 队友的实际作用 |
| --- | --- | --- |
| 第一晚 | 出生空地旁采木石，放工作台，造工具和篝火。目标栏显示缺多少材料，规划时显示可放位置。 | 可以多回合采木入共享库存，也可以守营地。遭遇时玩家撤到灯下，队友挡伤或合击。 |
| 经营家园 | 搭桥到潮汐滩，建屋、种菜、驯养，石镐解锁晶矿和灯具。施工一块块出现，资源、阻挡和保存与实物一致。 | 两人各负责一块下一步施工位，或一人探索一人备料，材料不足、位置被占用时如实停工。 |
| 远航与终章 | 岸林→潮滩→洞穴→高地。用桥和灯打开路线，收全地标与生物图鉴，挑战南岭守卫，把远航纪念品安在家。可继续走纯建造路线。 | 两处引灯机关提供同步开启的捷径，单人有可走的绕路；打首领可以轮流拉开仇恨、护送或带回掉落背包。 |

难度建议分为「家园」「生存」「远航」，分别压低生存压力、使用现有生存节奏、加强外区危险。保留现有存档难度及规则，正式调整前核对兼容；原型使用当前正式规则。回访动力来自未完成的屋子、有迹可循的潮汐事件、驯养和新区域，无需每天签到。施工、守夜、标记及物资进账由同一小岛状态提交。

## 迷雾摸金 · 2D 俯视带立面

**美术和镜头**。冷石、低照度、少量暖金。石墙有可辨的立面，已知区域、不可达、战斗威胁与撤离门能一眼区分。宝箱有轮廓和物件分级，动作后展示真实宝物名称、价值、重量及「入包／留在地面」。珍宝用独立造型和展陈灯光，不靠放大同一个宝石图标。固定俯视减轻瞄准与迷路的负担，保留远战看直线的读图空间。

| 阶段 | 玩家在做什么 | 队友的实际作用 |
| --- | --- | --- |
| 第一次带出 | 「轻松」先用一件近处宝物教会观察迷雾、撬箱、背包和守撤离门。找到出口后可直接撤；开箱消耗真实回合。 | 一个队友可掩护撬锁。守卫蓄力先给预警，再由玩家格挡或队友主动打断。 |
| 学会取舍 | 「标准」探索钟楼、共鸣石板与观测镜。拆钟换安全，或省工具给别处；轻声过机关与急跑形成真实取舍。出货之后判断是否回头。 | 队友可在已发现范围侦察和标路、捡地面实物，药剂有限；救援要走到身边，互相都能救。 |
| 长线 | 「险境」用不同巡守组合与路线考决策。跨局完成已有套装、扩包、比较装备与悬赏；最终目标是带回「晨星之核」并展出，之后轮换合约玩法。 | 两人能分头带宝、在出口集合。能看见谁交付了什么、谁实际存活到撤离范围。 |

关卡变化来自现有种子地形，增量可以先做一条观测镜—捷径—撤离的闭环，再加新怪物。参考《第五人格》的氛围、威胁读图与压力下协作；地图、怪物、宝物和界面采用露露机自己的表达。

## 其余四款

| 游戏 | 方向与手机布局 | 第一次 → 进阶 → 长线与协作 |
| --- | --- | --- |
| 深海回声 | 保留横屏，2D 平视侧横潜航。远处冷蓝剪影、中层礁体、近处潜艇灯。左移右声呐，氧量和归航方向靠边。 | 先找一个回声且返航，再跑五段回声与可选沉船。进阶去深区，回访补生物和航海日志、自己刷新安全航线。两人可分别驾驶与读声呐、标回程。独玩保留主动声呐。 |

| 快艇骰子 | 竖屏 2D 俯视骰桌。骰子置顶，单手可留骰和重掷，计分区突出本轮可填与预计得分，完整计分表可展开。 | 第一局教保留、重掷、填一个格；进阶按 13 轮计划上区奖励。保存最佳完整计分表、做自选挑战，允许单人破纪录、与角色对战或在团队模式讨论留骰。 |

深海方向沿用 `DeepSeaJourneyGame` 的真实潜航场景。后三款大厅入口带到已有网页样稿，新方案须独立审图并用正式回合验证。额外的五子棋旧网页入口不计入当前正式游戏馆六款。

## 审稿范围与工程取舍

- 四向触控和浏览器 UI 是预览层。碰撞、采集、施工成本、可执行队友动作、迷雾、敌人、开箱和撤离结果由仓库 Kotlin 文件运行；`world-core.js` 的旧玩法不参与两款新试玩。服务使用独立短期会话，回大厅可继续；进程结束后该试玩档到期。
- 小岛以原地图的真实地块投影 3D。远处海石、植被细节、地形高差属美术层，新增洞穴、海潮关卡等提案还需正式规则。可以在用户手机浏览器渲染，不需要用户安装 Blender。WebGL 不可用时，同一份 3D 网格走 Canvas 软件投影。开发侧首次启动需 Node、JDK、curl 和 Maven 下载。
- 本阶段用原生美术资源作大厅对照，局内为待审美术候选。通过网页审稿之后，再考虑用同一绘制层接 Android 状态桥，验证原生画面、帧时、安装前后旧档、语音和真人物行动。试玩队友由玩家选择 Kotlin 已允许的动作。
- 上游 MotionSites 对照案例为 **3D Collectible Hero** 的前后景关系、**Immersive Ocean** 的场景主导和留白、**Neo Museum** 的展品独立视觉焦点。使用其构图方法，页面的素材来自当前仓库原画和原创几何。

运行 `npm run preview`，打开 `http://127.0.0.1:4173/arcade/`。首次开局会编译 JVM 预览。可用 `node --test preview/tests/arcade-rules.integration.cjs` 复查采建、队友护卫与开箱撤离。若从局内返回大厅，「继续上次试玩」恢复该会话。

## 浏览器验证

- G-02：真实采木、采石、工作台材料扣除、通行阻挡、回到同一会话，以及手动操控试玩队友执行护卫，均通过 Kotlin 桥接测试。
- G-03：轻松难度用长矛和医师开局，撬箱取得「石刻铭牌」，撤离后同一宝物进入本局带出清单。结算后重复行动不会再推进回合。
- 在 Chromium 查看原画卡片与两张实玩地图，检查 390×844 竖握旋转、844×390 横屏、连续方向输入的命中换向逻辑、全岛切换、返回和继续。三项新集成测试及七项现有摇杆测试通过。旧 `world-core.test.cjs` 仍有一项既存建屋测试失败，和本次接入的 Kotlin 路线独立。
- G-02/03 的 Redmi 真机、角色连麦、正式存档与 UI 桥接仍待验。施工入口为同一绘制层与原生场景状态、动作回执的对照。
